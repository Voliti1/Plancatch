# 안전 마감일 화면

`main`의 통합 커밋 `75f9e3e`를 기준으로 `codex/frontend-safe-deadlines`에서 구현합니다.
계약은 `backend/docs/safe-deadlines-api.md`와 실제 Deadline 스키마·라우트를 기준으로 합니다.
백엔드·DB·배포 설정은 변경하지 않습니다.

## 사용 흐름

- 마감일 등록·수정에서 **안전 마감일 사용**을 켜고 여유시간을 일·시간·분으로 입력합니다.
- 새 마감일과 여유시간이 없는 기존 마감일은 미설정으로 시작합니다. 켜기만 하면 임의의 여유시간이 저장되지 않으며, 합계가 1분 이상이어야 합니다.
- 1일은 실제 경과시간 24시간입니다. 각 입력은 음수·소수 없는 정수이며, 빈 단위는 0으로 처리합니다. 시간·분을 23/59로 제한하지 않고 합계 분으로 변환합니다.
- 전체 합계는 1~2,147,483,647분입니다. 계산된 날짜가 서버의 날짜 범위를 벗어나면 서버 검증 오류를 표시합니다.
- 저장 후 목록·상세·대시보드의 마감일 행에서 **공식 마감**과 **안전 마감**을 한국 시간으로 구분합니다. 설정이 없으면 **미설정**입니다.
- 공식 마감일을 그대로 두고 여유시간만 변경할 수 있으며, 날짜를 변경하지 않았으면 원래의 초·밀리초를 보존합니다.
- 사용을 끄고 저장하면 여유시간을 `null`로 해제합니다. 공식 마감일은 유지합니다.

## API와 오류

기존 `POST /api/deadlines`, `PATCH /api/deadlines/{id}`에 `safety_buffer_minutes`만 추가합니다.
`safe_due_at`은 응답 전용입니다. 프론트엔드에서 계산해 전송하거나 서버 값 대신 표시하지 않습니다.
저장된 날짜 표시와 편집 입력은 구분되며, 오류가 나면 마지막 저장값과 수정 입력을 유지합니다.

저장 중 전체 폼을 잠그고 연속 제출을 막습니다. 422는 제목·공식 마감·여유시간/날짜 범위를 확인하도록 안내합니다.
404는 삭제되었거나 접근 불가능한 마감일 안내, 401은 기존 세션 제거·로그인 이동을 사용합니다.
과거의 공식·안전 마감도 등록할 수 있습니다. 목록 순서는 기존 공식 마감일 기준입니다.

연결된 작업의 가능 기간과 기존 일정 블록은 바꾸지 않습니다. 위험도·역산 계획·자동 배치·Google Calendar 동기화 기능은 포함되지 않습니다.

## 변경 파일

- `types/api.ts`: Deadline 응답 및 입력 여유시간 필드.
- `features/deadlines/safety-buffer.ts`: 일·시간·분 변환과 범위 검증.
- `features/deadlines/deadline-form.tsx`: 여유시간 사용·입력·해제, 연속 제출 방지.
- `features/deadlines/deadline-times.tsx`, 목록·상세, `app/globals.css`: 저장된 날짜 구분 및 PC/모바일 표시.
- `features/deadlines/api.ts`: 기존 API와 마감일 오류 안내.
- `tests/safe-deadlines.spec.ts`, 기존 테스트 응답: 합성 응답으로 폼·페이로드·시간대·보존·오류 확인.
- `live-tests/safe-deadlines.spec.ts`: 별도 전용 계정으로 실제 서버 저장·계산·새로고침·해제 검증.

## 검증

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

`npm test`는 합성 응답만 사용합니다. PC 테스트 시간대는 `America/Los_Angeles`이며 화면은 한국 시간입니다.
실제 서버 확인은 공개 기본 주소를 Node 테스트 환경변수 `PLANCATCH_LIVE_API_URL`로 설정하고 아래처럼 이번 테스트만 실행합니다.

```sh
npm run test:live -- safe-deadlines.spec.ts
```

PC·모바일 각각 새 전용 계정을 생성하며 토큰·임의 비밀번호는 메모리에서만 사용하고 출력하지 않습니다.
실제 검증에서는 trace·HAR·동영상·스크린샷을 저장하지 않습니다.
자신이 만든 `[테스트] Codex 안전 마감` 마감일만 삭제하고 조회 404까지 확인합니다.
계정 삭제 API가 없어 `plancatch-safe-test-*` / `전용 안전 마감 테스트` 계정은 남습니다.
이 검증은 로컬의 새 화면에서 배포 API로 전달한 요청이며 새 화면의 EC2 배포를 의미하지 않습니다.
테스트 후 일반 환경으로 build를 다시 실행합니다.

운영 환경변수는 기존 `NEXT_PUBLIC_API_BASE_URL` 그대로이며 새 키나 비밀 환경변수는 추가하지 않습니다.

Task·일정 블록이 새로 생성되지 않았습니다. 이번 검증의 마감일 2개는 삭제 후 404까지 확인했으며 전용 계정 2개는 남았습니다.
기존 AI 실제 서버 테스트는 이번 변경에서 재실행하지 않았습니다.
