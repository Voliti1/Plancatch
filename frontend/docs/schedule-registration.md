# 새 일정 등록 진입 화면

대시보드의 **자료 등록하기**는 `/sources/new`로 이동합니다. 대시보드에는 입력 폼을 배치하지 않습니다. 기존 원본 자료 목록의 등록 버튼도 같은 화면을 사용합니다. 기존 **새 일정 등록하기**와 사이드바 버튼은 `/deadlines/auto` 자동 등록 흐름을 유지하며, 두 경로를 서로 대체하지 않습니다.

등록 화면은 왼쪽 PDF·JPG 드롭 영역과 오른쪽 URL·텍스트 입력란으로 구성하며, 좁은 화면에서는 세로로 배치됩니다. 제목은 선택 입력입니다. URL과 텍스트 중 하나를 기존 `POST /api/sources` 계약으로 저장하고 원본 자료 목록으로 이동합니다. 두 입력란을 모두 채운 경우 하나를 선택하도록 안내하며 임의로 버리지 않습니다. 텍스트의 줄바꿈과 앞뒤 공백을 보존하고, 빈 내용과 HTTP/HTTPS 이외의 URL을 거부합니다. 실패 시 입력을 유지하고 저장 중에는 중복 요청을 막습니다.

현재 파일 업로드 API는 없습니다. PDF·JPG/JPEG는 드래그 또는 파일 선택으로 파일명·크기를 확인하고 제거할 수 있지만 브라우저 메모리에만 유지됩니다. 파일 본문 읽기, 서버 업로드, OCR/PDF 추출 또는 가짜 처리 완료를 수행하지 않습니다. 선택한 파일이 있으면 자료 저장을 차단하고 파일 제거 후 URL 또는 텍스트를 저장하도록 안내합니다. 페이지를 벗어나거나 새로고침하면 파일 선택이 사라집니다.

자료 저장만으로 마감일이나 작업·일정 블록이 생성되지 않습니다. 원본 자료 상세에서 원문 추출 → 외부 AI 전송 동의 → AI 분석·검토 → 마감일 승인 절차를 이어갑니다.

## 백엔드 후속 계약

실제 파일 등록을 연결하려면 인증된 파일 업로드 API의 경로와 요청 형식, 허용 형식·크기·개수, 응답 Source ID, 추출 상태·오류 및 삭제 정책을 먼저 합의해야 합니다. 이번 변경은 백엔드와 기존 API 계약을 수정하지 않습니다.

## 검증

- 로그인 보호와 대시보드 버튼을 통한 이동, 목록에서의 공통 진입
- PDF·JPG 선택/드롭, 중복 선택, 지원하지 않는 확장자·MIME 거부, 제거 및 파일 미전송
- 빈 입력·잘못된 URL·URL과 텍스트 동시 입력 차단
- URL·텍스트 저장 요청, 오류 후 입력 보존·재시도, 저장 중 중복 클릭 차단
- PC·모바일 배치, 가로 넘침 여부

브라우저 테스트는 `tests/schedule-registration.spec.ts`에서 테스트 전용 API 응답으로 실행합니다. 운영 데이터는 사용하지 않습니다.

이번 변경에서는 lint·TypeScript·프로덕션 빌드를 통과했습니다. 새 등록 화면 12건(PC·모바일)과 기존 로그인·자료 관리 등의 회귀 검증 20건을 확인했습니다. 실제 운영 서버와의 연동 검증은 수행하지 않았습니다.
