# 새 일정 등록 진입 화면

대시보드에는 **새 일정 등록하기** 버튼 하나를 두고, PDF·JPG·URL·텍스트를 입력하는 `/sources/new` 화면으로 바로 이동합니다. 옆에 별도의 **자료 등록하기** 버튼을 추가하지 않습니다. 사이드바의 **새 일정 등록하기**와 원본 자료 목록의 등록 버튼도 같은 입력 화면을 엽니다. 새 일정 버튼으로 재진입하면 제목·URL·텍스트와 선택한 파일이 초기화됩니다.

기존 URL 자동 등록은 입력 화면의 **URL 자동 등록 화면 열기** 링크로 `/deadlines/auto`에 진입합니다. 자동 등록의 명시적 동의·재개·오류 복구·AI 검토 기능은 유지합니다.

## 등록 방식

새 일정 등록 화면에서 **자료로 등록 / 수동 일정 등록**을 선택합니다. 왼쪽 작업 메뉴 대신 수동 등록 화면의 **등록한 일정 보기**로 기존 목록을 엽니다. 수동 등록은 기존 Task 폼·API를 재사용하며, 이름·마감일 연결·소요시간·우선순위·고정/유동 유형·가능 기간·설명·완료 여부를 저장합니다. 실제 일정 블록 배치나 Google Calendar 동기화를 수행하지 않습니다.

등록 방식만 전환하면 두 입력 초안과 선택한 파일을 유지합니다. 새 일정 버튼으로 다시 시작하면 모두 초기화합니다. 저장 중에는 등록 방식 전환을 잠그며, 실패하면 입력을 유지해 재시도할 수 있습니다. `?mode=manual`로 수동 모드에 바로 진입하고 선택적인 `deadline_id`로 기존 마감일 연결을 지정할 수 있습니다. 기존 Task 경로와 데이터는 유지합니다.

등록 화면은 왼쪽 PDF·JPG 드롭 영역과 오른쪽 URL·텍스트 입력란으로 구성하며, 좁은 화면에서는 세로로 배치됩니다. 제목은 선택 입력입니다. URL과 텍스트 중 하나를 기존 `POST /api/sources` 계약으로 저장하고 원본 자료 목록으로 이동합니다. 두 입력란을 모두 채운 경우 하나를 선택하도록 안내하며 임의로 버리지 않습니다. 텍스트의 줄바꿈과 앞뒤 공백을 보존하고, 빈 내용과 HTTP/HTTPS 이외의 URL을 거부합니다. 실패 시 입력을 유지하고 저장 중에는 중복 요청을 막습니다.

현재 파일 업로드 API는 없습니다. PDF·JPG/JPEG는 드래그 또는 파일 선택으로 파일명·크기를 확인하고 제거할 수 있지만 브라우저 메모리에만 유지됩니다. 파일 본문 읽기, 서버 업로드, OCR/PDF 추출 또는 가짜 처리 완료를 수행하지 않습니다. 선택한 파일이 있으면 자료 저장을 차단하고 파일 제거 후 URL 또는 텍스트를 저장하도록 안내합니다. 페이지를 벗어나거나 새로고침하면 파일 선택이 사라집니다.

자료 저장만으로 마감일이나 작업·일정 블록이 생성되지 않습니다. 원본 자료 상세에서 원문 추출 → 외부 AI 전송 동의 → AI 분석·검토 → 마감일 승인 절차를 이어갑니다.

## 백엔드 후속 계약

실제 파일 등록을 연결하려면 인증된 파일 업로드 API의 경로와 요청 형식, 허용 형식·크기·개수, 응답 Source ID, 추출 상태·오류 및 삭제 정책을 먼저 합의해야 합니다. 이번 변경은 백엔드와 기존 API 계약을 수정하지 않습니다.

## 검증

- 로그인 보호와 대시보드 버튼을 통한 이동, 목록에서의 공통 진입
- PDF·JPG 선택/드롭, 중복 선택, 지원하지 않는 확장자·MIME 거부, 제거 및 파일 미전송
- 빈 입력·잘못된 URL·URL과 텍스트 동시 입력 차단
- URL·텍스트 저장 요청, 오류 후 입력 보존·재시도, 저장 중 중복 클릭 차단
- PC·모바일 배치, 가로 넘침 여부

브라우저 테스트는 `tests/schedule-registration.spec.ts`에서 테스트 전용 API 응답으로 실행합니다. 운영 데이터는 사용하지 않습니다.

등록 진입 수정에서는 lint·TypeScript·프로덕션 빌드를 통과했습니다. 공통 등록 화면·URL 자동 등록·안전 마감일의 PC·모바일 브라우저 시나리오 58건을 확인했습니다. 모바일 포커스 검사는 브라우저 자동 스크롤과 실제 폼 배치 변경을 구분하도록 문서 좌표로 비교합니다. 테스트 전용 API 응답을 사용했으며 운영 서버 배포·실제 API 연동 검증은 수행하지 않았습니다.

수동 등록 통합에서는 lint·TypeScript·프로덕션 빌드와 PC·모바일 64건을 확인했습니다. 작업 메뉴 제거, 수동 생성 요청의 기존 계약·한국 시간 변환, 등록 방식 간 초안 보존, 새 등록 초기화, 저장 중 전환 차단·실패 후 재시도 및 기존 Task/Source/자동 등록 흐름을 검사합니다. 테스트 전용 API 응답을 사용하며 운영 반영은 별도 배포가 필요합니다.
