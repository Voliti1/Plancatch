# 원문 추출 → AI 마감일 검토

기준 브랜치는 `integration/frontend-tasks-live-ai`, 기준 커밋은 `472f9a1d3f7722004a1ed4fff1e598e804c81129`입니다. `codex/frontend-ai-review`에서 프론트엔드만 추가하며 백엔드 API·모델·DB·배포 설정은 변경하지 않습니다. `main`에 아직 없는 백엔드 변경을 PR에 섞지 않도록 PR 대상은 배포 기준 통합 브랜치입니다.

## 사용자 흐름

1. URL 또는 텍스트 자료 상세에서 **원문 추출**을 요청합니다. 추출 중에는 수정·삭제·중복 요청을 잠급니다.
2. `extracted` 상태는 원문 추출 완료입니다. AI 완료로 표시하지 않습니다. 공개 HTML/텍스트만 지원하며 로그인 우회·JavaScript 실행·PDF/이미지 추출은 지원하지 않습니다.
3. 추출 원문 전체가 Google Gemini로 전송됨을 안내하고 체크박스로 명시적 동의를 받습니다. 40,000 코드포인트를 초과하면 분석을 잠그고 자료를 나누도록 안내하며, 원문을 자르지 않습니다. 다시 추출한 내용이 바뀌면 기존 동의는 적용하지 않습니다.
4. 분석 시작 후 `/analyses/[id]`에서 진행 상태와 결과를 확인합니다. 자료 상세의 10건 단위 분석 기록에서도 결과를 다시 열 수 있습니다.
5. 원문 스냅샷, 주의사항, 각 후보의 근거·AI 신뢰도 참고값을 표시합니다. 신뢰도는 정확도를 보장하지 않습니다. 날짜가 불명확하면 직접 확인하거나 제외하도록 안내합니다.
6. 제목·마감일·설명·포함 여부를 수정하고 **검토 내용 저장**으로 서버의 새 revision을 적용합니다. 근거와 confidence는 읽기 전용입니다. 수정 내용이 남으면 승인할 수 없습니다.
7. 선택한 후보에 날짜가 있으면 승인합니다. 서버가 반환한 `approved_deadline_ids`로 생성된 마감일을 확인합니다. **전체 거부**는 별도 확인을 거치며 마감일을 만들지 않습니다. 승인·거부된 결과는 읽기 전용입니다.

승인은 마감일만 생성합니다. Task·일정 블록·역산 계획·안전 마감일·자동 배치·Google Calendar 동기화는 수행하지 않습니다.

## 요청 계약

| 동작      | 요청·본문                                                            |
| --------- | -------------------------------------------------------------------- |
| 추출 시작 | `POST /api/sources/{id}/analyze`, 본문 없음                          |
| 추출 조회 | `GET /api/sources/{id}`                                              |
| AI 시작   | `POST /api/sources/{id}/ai-analyses`, `allow_external_ai: true`      |
| 기록 조회 | `GET /api/sources/{id}/ai-analyses?limit=10&offset=0`                |
| 분석 조회 | `GET /api/ai-analyses/{id}`                                          |
| 후보 수정 | `PATCH /api/ai-analyses/{id}`, 현재 `revision`과 전체 후보           |
| 승인·거부 | `POST /api/ai-analyses/{id}/approve` 또는 `/reject`, 현재 `revision` |

각 수정 후보에는 `id`, `title`, `due_at`, `description`, `selected`만 전송합니다. 제외는 `selected: false`이며 후보를 목록에서 삭제하지 않습니다. 한국 시간 입력을 UTC로 전송하고, 날짜가 그대로면 원본 초·밀리초를 보존합니다.

## 조회·오류·입력 보존

추출과 분석의 자동 조회는 각각 2초 간격이며 한 번에 하나의 GET만 진행합니다. 최대 90초 후 안내와 함께 멈추고 사용자가 재시도할 수 있습니다. 완료·실패·요청 오류·페이지 이탈 시 타이머를 정리하며 진행 중 요청도 취소합니다. 브라우저 조회 중단은 서버 작업을 취소하지 않습니다. 영구 대기 작업의 복구는 백엔드 후속 과제입니다.

401은 기존 토큰 제거와 로그인 이동을 사용합니다. 404는 접근 불가능·삭제 안내, 409는 처리 중·검토 충돌·원문 변경 안내, 422는 입력 검증, 429는 처리 용량/한도, 503은 AI 설정 불가로 표시합니다. 서버의 추출·AI 오류 코드는 한국어 안내로 바꾸며 가짜 결과로 대체하지 않습니다.

저장·승인 실패 시 현재 검토 입력을 유지합니다. 최신 결과 조회가 입력을 덮어쓸 수 있으면 사용자가 명시적으로 입력을 버리고 불러오도록 확인합니다. 409 원문 변경은 자료로 돌아가 재추출·재분석하도록 안내합니다. 서버의 중복 승인 방지 정책을 유지합니다.

## 검증 실행

일반 `npm test`는 합성 자료·테스트용 AI 응답만 사용합니다. 테스트 내용에는 `[테스트]`를 표시하며 운영 코드에서 가져오지 않습니다. 동의·중복 클릭·진행 상태·조회 중단·빈 결과·날짜 불명확·전체 후보 저장·제외·승인·거부·충돌·입력 검증·로그인 만료와 PC/모바일 배치를 검사합니다.

실제 서버 검증은 별도입니다.

```powershell
$env:PLANCATCH_LIVE_API_URL = '팀에서 제공한 공개 API 기본 주소'
npm run test:live
```

새 프론트엔드를 로컬에서 실행하고 테스트 브라우저의 `/test-api/api` 요청을 해당 서버로 전달합니다. 따라서 실제 백엔드·DB·Gemini와 연결하지만 새 화면을 EC2에 배포한 것은 아닙니다. 배포 후 운영 origin에서 최종 확인은 별도입니다.

PC/모바일 각각 새 전용 계정을 만들고 임의 비밀번호를 메모리에서만 사용합니다. 테스트는 공개 URL 성공, 접근 제한 URL 실패, 텍스트 추출, 동의 후 실제 AI 분석, 후보 수정·승인, 새로고침 후 저장과 승인 재요청의 중복 방지를 확인합니다. 생성된 Task·일정 블록이 없는지도 확인합니다. 새로 만든 자료·마감일만 삭제하고 기존 사용자 데이터에는 접근하지 않습니다.

실제 토큰·비밀번호를 출력하지 않으며 trace·HAR·동영상·자동 스크린샷을 남기지 않습니다. 계정 삭제 API가 없어 `plancatch-test-*` / `전용 통합 테스트` 계정은 남습니다. 검증에는 실제 AI 호출 비용이 발생하므로 명시적인 `test:live` 실행에만 포함합니다. 테스트 후에는 일반 환경으로 `npm run build`를 다시 실행합니다.

## 변경 파일

- `app/(workspace)/analyses/[id]/page.tsx`: 보호된 결과 경로
- `features/analyses/`: 타입별 API·동의/기록·결과·검토·한국어 오류
- `features/sources/source-extraction.tsx`, `source-detail.tsx`, `api.ts`: 추출·자료 상태 연결
- `types/analysis.ts`, `lib/api/use-processing-poll.ts`: 분석 계약과 제한된 조회
- `app/globals.css`, 업무 메뉴·대시보드·자료 등록: 반응형 및 안내
- `tests/extraction.spec.ts`, `analyses.spec.ts`, `analysis-fixtures.ts`: 합성 응답 검증
- `live-tests/ai-review.spec.ts`, `playwright.live.config.ts`, `package.json`: 실제 서버 검증 분리
- README와 연동·PR 문서: 실행 및 인계

운영 환경변수는 기존 `NEXT_PUBLIC_API_BASE_URL`만 사용합니다. `PLANCATCH_LIVE_API_URL`은 Node 테스트 실행용 공개 주소이며 애플리케이션에 포함되지 않습니다. Gemini 키와 모델 설정은 기존 백엔드가 관리합니다.

## 실제 서버 검증 기록 — 2026-09-30

PC·모바일 각 1개 전체 흐름이 통과했습니다. 실제 API에 연결해 공개 URL·텍스트 추출 성공과 접근 제한 실패, Gemini 분석·수정·승인, 마감일 새로고침 후 유지와 한국 시간, 재승인 시 동일 ID 반환을 확인했습니다. 승인으로 Task·일정 블록이 생성되지 않았습니다. 이번에 만든 자료 6개와 승인 마감일 2개는 삭제 성공을 확인했고, 분석 기록도 원본 삭제 정책에 따라 정리됩니다. 계정 삭제 API가 없어 전용 테스트 계정 2개는 남아 있습니다. 비밀번호·토큰은 코드나 검증 문서에 보관하지 않습니다.
