# 작업 관리

`/tasks`에서 전체 작업을 조회하고 완료 상태·작업 유형으로 필터링합니다. 마감일 상세의 **이 마감일의 작업**에서는 해당 마감일에 연결된 작업만 조회하고 등록합니다. **작업 등록**은 `/tasks/new`, 제목 선택은 `/tasks/[id]`로 이동합니다. 업무 경로에는 기존 로그인 보호와 Bearer 인증을 적용합니다.

## 현재 API 계약

저장소의 `backend/app/schemas/task.py`와 `backend/app/api/routes/tasks.py`를 기준으로 연결했습니다. 백엔드 파일은 수정하지 않습니다.

| 동작           | 요청                               |
| -------------- | ---------------------------------- |
| 목록           | `GET /api/tasks?limit=50&offset=0` |
| 생성           | `POST /api/tasks`                  |
| 상세           | `GET /api/tasks/{task_id}`         |
| 수정·완료 처리 | `PATCH /api/tasks/{task_id}`       |
| 삭제           | `DELETE /api/tasks/{task_id}`      |

목록의 선택 필터는 `deadline_id`, `is_completed`, `schedule_type`입니다. 필터를 바꾸면 첫 페이지로 돌아갑니다. 연결할 마감일 선택지는 `GET /api/deadlines`의 100건 단위 페이지를 모두 불러옵니다. 조회 실패 시 저장을 잠그고 재시도를 제공합니다. URL의 마감일 값이 선택지에 없으면 다시 선택하거나 연결을 해제해야 합니다.

| 필드                           | 화면 동작                                    |
| ------------------------------ | -------------------------------------------- |
| `title`                        | 필수, 공백만 있는 이름 거부, 최대 255자      |
| `deadline_id`                  | 마감일 연결·변경·해제, 미선택은 `null`       |
| `description`                  | 선택 설명, 비어 있으면 `null`                |
| `estimated_minutes`            | 선택, 1~2147483647의 정수, 미정은 `null`     |
| `priority`                     | 현재 스키마의 1~5 값, 기본 3                 |
| `schedule_type`                | `flexible`(유동 작업) / `fixed`(고정 일정)   |
| `earliest_start`, `latest_end` | 선택, 둘 다 있으면 시작이 종료보다 빨라야 함 |
| `is_completed`                 | 완료·미완료 전환                             |

현재 계약에 우선순위 숫자의 높고 낮음이 정의되어 있지 않아 숫자에 임의의 긴급도 의미를 붙이지 않았습니다. 유형과 가능 기간을 저장해도 캘린더에 일정을 배치하지 않습니다. 마감일 이후의 가능 기간을 금지하는 등 서버 계약에 없는 제약을 추가하지 않습니다.

한국 시간으로 입력하고 UTC ISO 8601로 전송하며, 응답은 `Asia/Seoul`로 표시합니다. 제목 등 다른 필드만 수정할 때는 원본 날짜의 초·밀리초를 유지합니다. 선택 필드의 내용을 지우면 `null`을 전송합니다. 완료 전환 버튼은 `is_completed`만 수정하며 `completed_at`은 서버가 관리합니다.

저장 오류 시 입력을 보존합니다. 수정·삭제를 취소할 수 있고 삭제 확인 후 성공하면 작업 목록으로 이동합니다. 404는 없는 작업 안내, 401은 세션 제거·로그인 이동, 삭제 409는 연결된 캘린더 일정 때문에 삭제할 수 없다는 안내를 제공합니다. 실제 동기화 관리 화면은 아직 없습니다.

## 검증 및 실제 서버 확인

브라우저 테스트의 응답은 `tests/fixtures.ts`에 분리되어 있습니다. 실제 API를 호출하는 운영 코드에 mock을 넣지 않습니다. PC·모바일에서 마감일 연결 등록, 수정·취소, 날짜 정밀도 보존, 선택 필드 해제, 완료·미완료, 삭제·취소·409, 필터·페이지 이동, 101건 마감일 선택, 입력 검증, 오류·재시도 및 인증을 검사합니다.

실제 EC2의 Task API 배포 여부와 영구 저장은 별도 확인해야 합니다. 기존 `NEXT_PUBLIC_API_BASE_URL`을 사용하며 추가 환경변수는 없습니다. 실제 토큰·계정·비밀키를 테스트 파일이나 로그에 넣지 않습니다.

배포 담당자가 Task API를 제공한 뒤 마감일 상세에서 작업을 등록하고, 새로고침 후 내용 유지 → 수정 → 완료 → 미완료 → 삭제를 확인합니다. 가능 일시를 한국 시간으로 입력했을 때 상세 표시가 동일한지도 확인합니다.

## 남은 기능과 API 협의

이번 CRUD에는 추가 API가 필요하지 않습니다. 다음 기능은 구현하지 않았으며 가짜 결과를 표시하지 않습니다.

- AI 분석 결과 확인·수정·승인과 역산 작업 계획
- 작업 간 선후 관계, 안전·내부 마감일, 마감 위험도
- 자동 일정 배치·미리보기·사용자 승인·재배치
- Google Calendar 연결과 동기화 관리

다음 단계에는 분석 결과·진행 상태·수정·승인 계약, 작업 의존 관계의 조회·수정 계약, 우선순위 해석, 일정 미리보기·승인 계약을 백엔드와 협의해야 합니다. Scheduled Event CRUD만으로 자동 배치나 Google Calendar 연동이 완성된 것으로 간주하지 않습니다.
