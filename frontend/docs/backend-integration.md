# 백엔드 연동 인계

## 첫 MVP에 필요한 연동 조건

현재 `backend/app/schemas`와 `backend/app/api/routes`의 실제 필드와 경로를 기준으로 연결했습니다. 첫 MVP에 새로운 CRUD API는 필요하지 않습니다.

1. **CORS**: 현재 `backend/app/main.py`에는 CORS 미들웨어가 없습니다. 프론트엔드와 API의 origin이 다르면 프론트엔드 origin을 허용하고 OPTIONS preflight, Authorization/Content-Type 헤더, GET/POST/PATCH/DELETE를 허용해야 합니다. 실제 배포 환경에서 다른 계층이 이미 처리하는지는 확인이 필요합니다. 이 작업은 백엔드/배포 담당자 범위입니다.
2. **HTTPS**: HTTPS 프론트엔드에서 HTTP API로 요청하면 혼합 콘텐츠 제한에 걸립니다. 배포 담당자가 브라우저에서 접근 가능한 HTTPS API 주소를 제공해야 합니다.
3. **현재 사용자**: `/api/auth/me`는 Bearer 인증이며, 프론트엔드 보호 화면 진입 시 이를 확인합니다. 401은 로그아웃으로 처리합니다.
4. **날짜**: `due_at`은 UTC offset을 포함한 ISO 8601로 요청합니다. 응답 날짜도 `Z` 또는 offset을 포함해야 합니다.
5. **페이지 정보**: 현재 목록은 배열 응답이라 전체 개수는 알 수 없습니다. 향후 정확한 통계가 필요하면 total/count 또는 요약 API가 필요합니다.

## 이후 API 협의 사항 — 현재 연결하지 않음

최종 원격 확인에서 `main`의 `ad1d84b`까지 반영했습니다. 작업 도중 Task 및 Scheduled Event CRUD가 저장소에 추가되었습니다. 해당 API의 배포 여부는 확인하지 않았으며 이번 프론트엔드 범위에서는 연결하지 않았습니다. 아래 항목은 다음 작업에서 실제 계약과 제품 요구사항을 대조할 내용입니다.

- 실제 파일 업로드: 허용 형식·용량, 업로드 URL/완료 처리, 실패 및 재시도 상태.
- AI 분석: 분석 실행·진행 상태·결과 조회, 근거·신뢰도, 결과 수정 및 승인.
- Task CRUD: 완료 상태, 예상 소요 시간, 연결된 마감일, 선후 관계.
- 안전/내부 마감: 계산 결과와 사용자 수정 값, 위험도 산정 기준.
- 자동 일정: 미리보기 생성·버전·사용자 승인·재배치·충돌 처리.
- Scheduled Event CRUD: 작업 연결, 시작/종료 시각, 승인 상태.
- Google Calendar: 연결 시작·콜백·연결 상태·해제, 동기화 상태·오류·재시도.

기존 Task 및 Scheduled Event API는 백엔드 문서에서 확인할 수 있습니다. 그 외 미래 기능의 경로와 계약은 별도 협의가 필요하며 프론트엔드에서 임의의 API를 호출하지 않습니다.

## 실제 서버 확인 절차

실제 API 주소가 설정되지 않은 환경에서는 아래 검증을 완료한 것으로 간주하지 않습니다. 비밀키나 실제 토큰을 코드, 문서, 로그에 복사하지 않습니다.

1. 로컬 `.env.local`에 공개 API 주소를 설정하고 개발 서버를 재시작합니다.
2. 브라우저에서 회원가입 → 로그인 → 사용자 이름 확인 → 새로고침 유지 확인.
3. URL과 텍스트를 등록하고 목록을 새로고침해 영구 저장 여부 확인.
4. 마감 생성 → 한국 시간 확인 → 수정 → 새로고침 → 삭제 확인.
5. 로그아웃 후 보호 URL에 직접 접근하면 로그인으로 이동하는지 확인.
6. 모바일과 PC에서 폼·오류·빈 목록·페이지 이동을 확인.

요구사항 파일 `PlanCatch_요구사항_정의서_차별화기능추가.xlsx`는 작업 시작 시 저장소에 없었습니다. 전달된 첫 번째 작업 범위를 기준으로 구현했습니다.
