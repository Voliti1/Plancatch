# 원본 자료 상세·수정·삭제

원본 자료 목록에서 **상세 보기**를 선택하면 `/sources/[id]`로 이동합니다. 로그인한 사용자의 자료만 기존 백엔드 API로 조회하고 수정·삭제합니다.

## API

| 동작      | 요청                              |
| --------- | --------------------------------- |
| 상세 조회 | `GET /api/sources/{source_id}`    |
| 수정      | `PATCH /api/sources/{source_id}`  |
| 삭제      | `DELETE /api/sources/{source_id}` |

수정 요청에는 `title`과 현재 자료 유형의 `original_url` 또는 `original_text`만 포함합니다. 빈 제목은 `null`, 텍스트는 줄바꿈과 공백을 보존합니다. `source_type`, 추출 결과, 처리 상태는 수정하지 않습니다.

제목·원본·추출 내용·처리 상태와 한국 시간의 등록/수정 일시를 표시합니다. 자료 유형이 URL/텍스트가 아닌 경우 상세 조회·삭제만 제공합니다.

수정 취소 시 저장된 상세 화면으로 돌아갑니다. 실패 시 입력값을 유지하고 오류를 안내합니다. 삭제 취소는 API 요청을 보내지 않으며, 확인 후 삭제에 성공하면 목록으로 돌아갑니다. 삭제 실패 시 상세 화면에서 다시 시도할 수 있습니다. 중복 저장·삭제 요청은 처리 중 잠급니다.

404 응답에는 삭제되었거나 접근 불가능한 자료라는 안내와 목록 복귀 링크를 제공합니다. 401은 기존 인증 처리에 따라 세션을 지우고 로그인 화면으로 이동합니다.

기존 백엔드의 외래 키 정책(`ON DELETE SET NULL`)에 따라 자료를 삭제해도 연결된 마감일은 유지됩니다. 기존 마감일과 해당 원본 사이의 연결은 해제됩니다.

## 검증 범위

브라우저 테스트는 실제 스키마에 맞는 테스트 전용 응답을 사용합니다. URL/텍스트 수정 후 새로고침, 수정·삭제 취소, 삭제 성공·실패, 잘못된 URL·빈 텍스트, 저장 실패 후 입력 보존, 인증 보호·401·404·로딩을 PC/모바일에서 검사합니다. 실제 운영 서버의 데이터 변경 검증은 별도입니다.

자료 관리 테스트 8개와 기존 기능 검사 12개가 통과했습니다. lint, TypeScript 검사, 일반 환경의 build도 통과했으며 PC 상세 화면과 모바일 수정 화면을 캡처해 배치를 확인했습니다. 추가 환경변수나 백엔드 API 변경은 필요하지 않습니다.

## PR 설명

제목: `feat(frontend): add source details, editing and deletion`

원본 자료 목록에 상세 보기 경로를 추가하고 기존 Source API로 조회·수정·삭제를 연결합니다. 제목과 URL/텍스트를 수정할 수 있으며, 삭제는 사용자 확인 후 처리합니다. 입력 검증, 취소, 오류 재시도, 처리 상태와 한국 시간 표시를 포함합니다. 백엔드 및 배포 설정 변경은 없습니다.

대상: `feature/frontend-base` → `main`
