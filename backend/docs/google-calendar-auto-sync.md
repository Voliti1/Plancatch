# Google 캘린더 자동 반영

Google 계정이 연결된 사용자의 마감일·고정 할 일·확정 배치를 등록·수정·삭제하면 서버가 Google 기본 캘린더에 자동 반영합니다. 자연어 등록과 URL·이미지·텍스트 검토 후 마감일 승인도 같은 경로를 사용합니다. 전송 미리보기나 두 번째 등록 확인은 필요하지 않습니다. 일정 상세의 완료 처리 버튼은 제거하고 기존 완료 데이터와 목록의 완료 기능은 유지합니다.

## 범위와 화면

- 확인한 마감일은 공식 마감 시각부터 1분 길이로 표시합니다. 안전 마감일·원문·메모는 보내지 않습니다.
- 고정 할 일은 유효한 시작·종료가 있고 배치가 없을 때만 전송합니다. 배치가 있으면 확정 배치만 보냅니다. 유동 작업의 가능 기간과 미확정 배치는 보내지 않습니다.
- 변경된 제목·실제 시간을 반영하고, 로컬 삭제 시 관리 중인 Google 사본도 삭제합니다. 마지막 연결 마감일의 원본/분석/이미지 정리는 기존 규칙을 유지합니다.
- 다른 앱이 만든 Google 일정, Google에서 가져온 읽기 전용 일정은 수정하지 않습니다. Google에서 바뀐 내용을 로컬에 자동 반영하는 양방향 기능은 포함하지 않습니다.
- 상세 화면은 반영 중·완료·다시 시도 중·연결 필요·실패를 표시합니다. 대기 중에는 상태만 조회합니다. 일시 실패는 서버가 이어 처리하며, 해결이 필요한 실패에는 연결 확인/다시 시도를 제공합니다.
- 기존 기록을 배포만으로 일괄 전송하지 않습니다. 이전 일정은 상세의 ‘지금 동기화’로 시작할 수 있고 이후 변경은 자동입니다. 연결 전 만든 일정을 새 연결만으로 한꺼번에 전송하지 않습니다.

## 저장·재시도·충돌

로컬 변경과 전송할 최신 제목/시간을 같은 DB 트랜잭션으로 저장합니다. 브라우저를 닫아도 처리하며 앱 재시작 뒤에도 대기 내용을 읽습니다. 짧은 간격의 수정은 최신 상태로 합치되, 이미 저장한 실행 의도는 결과를 먼저 확인한 뒤 다음 변경을 반영합니다.

생성 ID는 전송 전에 영구 저장합니다. 수정·삭제는 기존의 조건부 요청과 실행 의도를 재사용합니다. 응답 유실은 같은 ID/작업을 먼저 조회해 중복 생성을 막습니다. 등록 직후 삭제해 Google 사본이 아직 없으면 새로 생성하지 않습니다. 고정 할 일↔배치 전환은 이전 사본을 제거한 뒤 새 사본을 생성합니다.

Google에서 직접 바꾼 제목·시간/소유 표시·참석자·반복/특수 일정은 덮어쓰지 않고 실패 상태로 안내합니다. ETag/If-Match는 실행 사이의 변경도 보호합니다. Google에서 추가한 메모·알림은 수정 시 유지하며 사본 삭제 시 함께 삭제됩니다. 이전 연결의 대기 내용을 새 Google 계정으로 보내지 않습니다. 계정 변경·권한 만료는 연결 확인이 필요합니다.

일시 오류는 15초부터 최대 1시간까지 간격을 늘려 총 10회 미만의 자동 재시도를 예약합니다. 실패가 지속되면 자동 반복을 멈추고 사용자가 재시도할 수 있습니다. 원문·비밀·외부 응답을 로그에 기록하지 않습니다. [조건부 변경](https://developers.google.com/workspace/calendar/api/guides/version-resources)과 [Google 오류 처리](https://developers.google.com/workspace/calendar/api/guides/errors)를 참고했습니다.

소유자 잠금으로 로컬 변경·전송·연결 변경을 직렬화합니다. 외부 요청은 각각 제한 시간이 있으며 저장 요청은 실행 중인 같은 계정 작업을 잠시 기다릴 수 있습니다. 화면의 변경 요청 제한 시간은 60초입니다. 다른 계정 작업의 잠금은 기다리지 않고 다음 처리로 넘깁니다.

## DB·실행·복구

Migration20261102_0010은 google_calendar_exports에 desired_payload·sync_pending·sync_attempts·retry_at과 대기 조회용 인덱스만 추가합니다. 기존 행의 sync_pending은 false이며 구조 변경이 과거 일정 전송을 시작하지 않습니다. 별도 외부 라이브러리·cron·서비스·OAuth 권한은 추가하지 않습니다.

FastAPI 수명 주기에서 대기 작업을 처리합니다. DB를 대체한 단위 검사에서는 실제 처리기를 시작하지 않습니다. 종료 시 제한된 작업을 마친 뒤 종료하고, DB 장애 시에는 대기 기록을 유지합니다. 이전 코드로 복구할 때도 DB 필드와 대기 내용을 유지하며 downgrade하지 않습니다. 이전 코드에서는 자동 처리가 멈추므로 미처리 변경은 새 버전으로 복귀한 뒤 이어 처리해야 합니다. 코드 복구는 실제 Google 변경을 되돌리지 않습니다.

`GET /api/integrations/google-calendar/auto-sync?kind=...&item_id=...`는 본인 상태만 읽습니다. `POST`의 본인 kind/item_id는 기존 일정 전송 또는 실패 재시도를 예약합니다. GET·캘린더 조회만으로 외부 쓰기를 실행하지 않습니다. 이전 수동 전송 API는 호환용으로 남기되 자동 작업 중인 항목의 수동 변경은 거절합니다.

가상 Google 응답과 격리된 DB로 생성/수정/삭제·응답 유실·계정 분리·자료 승인·자연어 등록·종류 전환을 검사합니다. 실제 개인 Google 캘린더 쓰기 성공은 별도 사용자 확인 대상으로 구분합니다.
