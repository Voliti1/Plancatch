# 사람인 접수기간과 남은 기간

- 공식 사람인 호스트의 `/zf_user/jobs/view`, `/zf_user/jobs/relay/view`와 단일 숫자 `rec_idx`에서만 전용 처리를 적용한다. 다른 사이트의 기존 본문/JSON-LD 추출은 유지한다.
- 공개 HTML의 보이는 `jv_cont jv_howto` 안에서 `info_period`의 직접 자식 `dt/dd`를 짝지어 시작일/마감일을 구분한다. 완전한 연도·날짜·시간을 검증하고, 기존 서비스 기본값인 한국 시간을 적용한다. 날짜나 시간이 없으면 만들어 넣지 않는다.
- 같은 영역의 `info_timer .day/.time`은 **추출 당시 사이트 표시값**으로만 기록한다. `data-remain-time`은 단위가 보장되지 않은 원문 속성으로만 보관하며 날짜 계산에 사용하지 않는다. 명시 마감일을 타이머로 덮어쓰거나 현재 시각에 더하지 않는다.
- 숨김/탐색/로그인 영역, 다른 사이트/경로/모호한 공고 ID, 충돌 접수기간, 올바르지 않은 날짜, 과도한 영역·쌍·타이머를 보수적으로 처리한다. 암호 입력/robots/공개 DNS/TLS/크기·시간 제한을 우회하지 않는다. 추가 요청·JavaScript·onclick 실행 없음.
- `AnalysisResponse.source_period`는 저장된 `input_text`에서 계산하는 선택적 응답 필드다. `start_text`, `end_text`, `deadline_at`, `remaining_text`, `has_conflict`를 제공하며, 과거 분석은 `null`이다. 모델/테이블/마이그레이션/사용자 데이터는 변경하지 않는다.
- AI는 접수 시작일과 상대 타이머를 마감일로 취급하지 않는다. 완전한 `YYYY.MM.DD HH:mm` 근거도 한국 시간 정책으로 검증한다. 접수기간 충돌/마감 미확정/AI 날짜 불일치는 자동 등록하지 않는다. 동의·소유권·원문 hash·revision·중복 방지는 그대로 유지한다.
- 프론트엔드는 원문 시작/마감일, 추출 당시 사이트 타이머, 원문 마감일까지의 현재 남은 시간을 구분한다. 후보 수정 시 수정 중인 날짜의 잠정 계산임을 표시한다. 이미 승인한 분석은 당시 후보의 날짜 기준이며 이후 마감일 상세에서 수정한 날짜를 다시 조회하지 않는다.
- 현재 남은 시간은 기기 시계를 사용하며 1초마다 갱신한다. 사이트 날짜 변경을 실시간 감시하지 않는다. 예전 자료는 `원문 다시 추출` 후 새 AI 분석이 필요하다. 기존 분석 기록을 자동 수정하지 않는다.
- 공개 공고 55170548의 실제 서버 HTML에서 시작 2026.10.01 00:00 / 마감 2026.11.01 23:59를 확인했다. 타이머 본문은 `0일 00:00:00` 초기값 형태다. 타이머의 0으로 마감 처리하지 않으며, 미래 마감일과 함께 나타나면 초기값 가능성을 안내한다.

## 검증

`tests/test_saramin_period.py`는 합성 HTML/모델 응답으로 날짜/시작일/영역/호스트/숨김/충돌/한계/타이머/응답 계약을 검사한다. 기존 전체 백엔드 테스트와 함께 실행한다.
`frontend/tests/remaining-period.spec.ts`는 합성 응답과 고정 시계로 PC·모바일 현재/스냅샷 구분, 초 단위 갱신, 입력 변경·저장, 마감됨/미확정, 구 버전 호환과 가로 넘침을 검사한다.
