# 안전 마감일 API — SAFE-01/02 및 SAFE-03 화면용 데이터

요구사항 정의서 `PlanCatch_요구사항_정의서_차별화기능추가.xlsx`의
`요구사항 정의서_000기능!D100:I102` 기준으로 구현한다.
프론트엔드 화면, 자동 배치, 위험도, AI 역산 계획, Google Calendar 동기화는
이번 변경에 포함되지 않는다.

## 저장 및 계산 규칙

- `due_at`: 원래의 **공식 마감일**. 안전 마감 설정으로 덮어쓰지 않는다.
- `safety_buffer_minutes`: 사용자가 마감일별로 선택한 여유시간을 분 단위로 저장.
  양의 정수만 허용(1~2,147,483,647). 1일 전=1440, 3시간 전=180.
- 미설정 또는 명시적 `null`: 안전 마감 기능 미사용. 기본 1일 등의 임의 설정 없음.
  0은 허용하지 않는다. 비활성화는 `null`로 전송한다.
- `safe_due_at`: **공식 마감일 − 여유시간**. 응답 전용 필드로 두 저장값에서
  계산한다. 별도의 중복 날짜 컬럼을 두지 않으므로 공식 날짜/여유시간 변경 시
  항상 새 값으로 조회된다. 클라이언트가 직접 전송하면 422.
- 모든 입력 날짜는 시간대가 필수이며 UTC로 정규화한다. 1일은 실제 경과시간
  24시간이며 영업일/공휴일/현지 달력일 규칙을 적용하지 않는다.
- 과거의 공식/안전 마감도 저장 가능하다. 계산 결과가 지원 날짜 범위를 벗어나면
  422로 거부한다. PATCH는 기존 값과 새 값을 결합해 검증하고 실패 시 기존 값 유지.
- 여유시간 변경은 연결된 Task의 가능 기간이나 이미 생성된 일정 블록을 수정하지
  않는다. 미래 자동 배치 단계에서 두 데이터를 함께 검증해야 한다.
- AI 승인으로 생성되는 마감일도 여유시간은 미설정이다. 사용자가 설정해야 한다.

## 기존 CRUD 경로 그대로 사용

로그인 토큰과 소유권 확인은 기존과 동일하다. 다른 사용자의 데이터는 404.

`POST /api/deadlines`

```json
{
  "title": "보고서 제출",
  "due_at": "2026-10-05T18:00:00+09:00",
  "safety_buffer_minutes": 180
}
```

응답(일부):

```json
{
  "due_at": "2026-10-05T09:00:00Z",
  "safety_buffer_minutes": 180,
  "safe_due_at": "2026-10-05T06:00:00Z"
}
```

`GET /api/deadlines`, `GET /api/deadlines/{id}`,
`PATCH /api/deadlines/{id}`에 두 안전 마감 필드를 포함한다.
목록은 기존대로 공식 마감일 오름차순이며 안전 마감순 정렬은 하지 않는다.

PATCH 예시:

```json
{"safety_buffer_minutes":1440}
```

끄기:

```json
{"safety_buffer_minutes":null}
```

PATCH에서 이 필드를 생략하면 기존 여유시간을 유지한다.
`due_at`만 수정해도 안전 마감은 즉시 재계산된다.

## 프론트엔드 담당자 연결 사항

1. Deadline 타입에 `safety_buffer_minutes: number | null`,
   `safe_due_at: string | null` 추가.
2. 생성/수정 화면에서 여유시간 사용 여부 및 일/시간/분 입력 제공.
   분 단위 정수로 변환해 전송. 초기값 임의 생성 금지.
3. 상세/목록에서 공식 마감과 안전 마감을 라벨로 구분해 동시에 표시.
   화면 시간대는 기존 정책에 따라 변환하고 null은 ‘미설정’으로 표시.
4. 범위/형식 오류 422 및 소유권 오류 처리. 안전 마감이 지났다고 API 자체가
   실패하는 것은 아니며 자동 배치/캘린더 반영이 완료된 것처럼 표시하지 않는다.

## 마이그레이션과 복원

`20260930_0006`은 deadlines에 nullable 정수 컬럼과 양수 CHECK만 추가한다.
기존 마감일/계정/작업 데이터와 날짜는 변경하지 않는다.
이전 코드로 복구해도 추가 컬럼은 유지한다. 자동 downgrade로 사용자 여유시간을
삭제하지 않는다. 적용 전 DB 구조만 별도 백업한다.
