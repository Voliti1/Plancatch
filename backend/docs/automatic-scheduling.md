# 자동 배치 미리보기

시간 미정인 유동 할 일을 소요시간만큼 빈 시간에 나누어 제안한다. 마감일이 빠른 순서,
같은 기한이면 우선순위가 높은 순서로 배치하는 결정적 방식이다. AI 호출이나 최적해 보장은 없다.

## 사용자 흐름

1. 수동 일정 등록에서 유동 작업과 소요시간을 설정한다.
2. 자동 배치에서 할 일, 최대 31일의 기간, 한국 시간 기준 작업 시간·요일을 선택한다.
3. 미리보기에서 시작 시간을 옮기거나 할 일 전체를 제외한다.
4. 승인 직전 재검증 후 확정 배치를 저장한다. 연결된 Google에는 기존 자동 동기화로 전송한다.

자동 배치 상단의 ‘배치 기록’에서 이전 기록을 다시 연다. 상태 필터·10개씩 이전/다음
페이지를 지원한다. 승인 당시 시간은 영수증으로 보존하며, 현재 배치가 변경·삭제·취소됐는지는
별도 개수로 표시한다. ‘기록 보기 · 배치 관리’로 이동한 뒤 저장한 배치를 수정·삭제한다.
조회는 Google 호출이나 쓰기를 하지 않는다. 목록 새로고침으로 현재 상태를 다시 확인한다.

미리보기는 할 일·캘린더·Google 일정을 변경하지 않는다. 승인한 배치는 이 화면의
‘저장한 배치 관리’에서 기존 배치 API로 수정·삭제할 수 있다. 일정 상세의 배치 입력은 복원하지 않는다.

## 범위와 보호

- 계정별 할 일 20개, 배치 200개, 미리보기 15분, 미승인 기록 최근 30개(만료 포함).
  새 미리보기를 만들면 오래된 미승인 기록부터 정리한다. 승인 기록은 삭제하지 않는다.
  이전 버전에서 이미 정리한 만료 미리보기는 복원하지 않는다.
- 완료·고정·반복·개별 반복 회차·이미 승인된 배치가 있는 할 일은 제외한다.
- 소요시간 전부를 배치할 수 없으면 그 할 일 전체를 제외하고 이유를 표시한다.
- 가능 기간, 연결된 안전 마감일(없으면 공식 마감일), 작업 시간·요일을 지킨다.
- 로컬 고정·반복 일정 및 확정 배치를 피한다. 종류별 최대 1,000개를 확인하며
  상한이나 파싱 문제로 누락 가능성이 있으면 승인을 차단한다.
- Google 포함 시 연결된 기본 캘린더의 바쁨 일정만 확인한다. 종일·반복 회차를 포함하고
  일치하는 플랜캐치 전송 사본은 로컬에서 검사한다. 첫 페이지 250건 제한이나 조회 실패는
  명시적으로 알리고 승인을 막는다. 사용자가 Google 제외로 새 미리보기를 만드는 것은 가능하다.
- 승인 직전에 현재 로컬 상태와 Google을 다시 확인한다. 로컬 변경은 소유자 잠금으로
  직렬화하되 외부 Google 일정에 대한 원격 예약은 아니다. Google 조회 직후 다른 앱이
  추가하는 일정까지 원자적으로 막지는 못한다.
- 승인 시 길이·가능 시간·미래 시각·겹침·소유권·소요시간 전체 선택을 서버에서 검증한다.
- 승인 기록과 배치를 한 트랜잭션으로 저장한다. 동일 계획 재승인은 기존 영수증을 반환한다.
  배치를 나중에 지웠어도 재시도로 되살리지 않는다. 별도 새 미리보기로 재배치해야 한다.
- Google 조회 중 자격 증명 회전은 기존 정책대로 보존한다. 제목·토큰·참석자를 계획에 저장하지 않는다.

## API

모든 경로는 인증된 현재 계정으로 제한되며 `Cache-Control: no-store`를 사용한다.

- `GET /api/scheduling/tasks?q=`: 미완료 유동 작업 첫 100개와 `has_more`.
- `POST /api/scheduling/preview`: `task_ids`, `start_at`, `end_at`,
  `day_start_minutes`(기본 540), `day_end_minutes`(1080),
  `weekdays`(월=0~일=6, 기본 평일), `chunk_minutes`(15~240, 기본 60),
  `include_google`(기본 true). 시간은 시간대가 명시된 형식이다.
- `GET /api/scheduling/plans/{id}`: 본인 계획 조회.
- `GET /api/scheduling/plans`: 본인 기록 요약. `state=all|pending|approved|expired`,
  `limit` 기본 10·최대 20, 이어보기는 응답 `next_cursor`의 `created_at`·`id`를
  `before_at`·`before_id` 쌍으로 전달한다. 생성 시각·ID 역순으로 같은 시각도 안정적으로
  탐색한다. 목록에 원본 요청·배치 전체·Google 정보를 실어 보내지 않는다.
- 기록 요약 및 단건 조회의 `saved_state`는 승인 배치의 현재 `active_count`,
  `changed_count`(시간 변경), `deleted_count`, `inactive_count`다. 시간 변경 개수는
  현재 존재하는 배치 중 승인 시간과 다른 개수이며 활성/미표시 개수와 중복될 수 있다.
- `POST /api/scheduling/plans/{id}/approve`: `blocks: [{id,start_at,end_at}]`.
  계획에 있는 블록만 승인할 수 있고 같은 할 일의 블록은 모두 선택하거나 모두 제외한다.

응답에는 `id`, `request`, `blocks`, `details`(작업 요약·제외 이유·경고·Google 확인 상태),
`expires_at`, `approved_at`, `approved_event_ids`가 있다. 유효 시간이나 원본이 바뀌면 409,
잘못된 블록 편집은 422, 타 계정 참조는 404다.

## DB와 복구

`20261110_0015`는 `schedule_plans` 테이블과 소유자·만료 인덱스만 추가한다.
기존 할 일과 배치 열은 바꾸지 않는다. 직전 #122 코드·화면은 기존 ScheduledEvent를
계속 읽을 수 있으므로 코드·빌드를 함께 복구할 수 있다. 새 테이블·승인 기록과 사용자
데이터는 남기며 운영 DB 다운그레이드나 데이터 덮어쓰기는 하지 않는다.
