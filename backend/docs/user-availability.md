# 계정별 가능 시간과 날짜별 예외

`/planning/availability`에서 요일별 여러 시간대와 특정 날짜의 예외를 저장한다.
기본은 평일 09:00~18:00(한국 시간)이며 저장하지 않은 계정에는 이 값을 반환할 뿐 DB 행을 만들지 않는다.
하루 최대 8개 시간대, 날짜별 예외 최대 366개다. 시간대가 없는 요일/날짜는 쉬는 날이다.
날짜 예외는 해당 요일의 기본 시간을 완전히 대체한다. 예외를 삭제하면 기본 시간으로 돌아간다.

시간은 자정 기준 분 단위(시작 0~1439, 종료 1~1440)이며 1440은 그날 끝 자정이다.
자정을 가로지르는 시간은 이틀로 나눈다. 겹치는 구간·역순·중복 요일/날짜는 거절하고,
서로 붙어 있는 구간은 허용한다. 요일/시간/수정 번호에는 bool·소수·문자열을 허용하지 않는다.
누락한 요일은 쉬는 날로 정규화한다. 날짜는 YYYY-MM-DD만 받는다.

## 저장과 자동 배치

- `GET /api/scheduling/availability`: 현재 계정의 `revision`, 고정 `timezone=Asia/Seoul`,
  `weekly:[{weekday:0..6, intervals:[{start_minutes,end_minutes}]}]`,
  `exceptions:[{date, intervals:[...]}]`. `Cache-Control: no-store`.
- `PUT /api/scheduling/availability`: 같은 형식의 전체 교체. 읽은 revision을 반드시 보낸다.
  최초 번호는 0, 저장 후 1씩 증가. 다른 창에서 바뀌었으면 409로 거절하고 현재 설정을 보존한다.
  임의 user_id는 받지 않으며 인증한 계정만 읽고 수정한다. 계정 삭제 시 설정도 함께 삭제한다.
- 자동 배치 입력 `use_saved_availability=true`이면 저장한 시간·날짜 예외를 사용한다.
  false(기존 클라이언트 기본값)이면 종전 요청의 하루 시작/종료·요일을 사용한다.
  화면에서 ‘저장한 가능 시간과 날짜별 예외 사용’을 선택하거나 설정 화면의
  ‘이 시간으로 자동 배치’로 진입한다. 날짜 범위·한 번에 작업할 시간·Google 포함 여부는 계속 선택한다.
- 가능한 시간에서 로컬 고정/반복 일정·확정 배치와 선택한 Google 바쁨 일정을 뺀 뒤 제안한다.
  설정 저장만으로 기존 일정이나 Google 일정을 변경하지 않는다. 승인해야 실제 배치가 생긴다.
- 저장한 시간으로 만든 미리보기는 계정 설정의 revision·정규화한 내용까지 snapshot에 포함한다.
  가능 시간이 바뀌면 새 미리보기가 필요하며 승인 시 같은 시간대를 다시 검증한다.
  설정 저장·계획 승인은 기존 user 행 잠금을 공유한다. 다른 계정 변경은 영향을 주지 않는다.
- 이미 승인한 계획의 재승인은 기존 영수증을 그대로 반환한다. 설정 변경으로 되살리거나 이동하지 않는다.
  직접 입력한 시간을 사용하는 기존 미리보기는 계정 설정 변경의 영향을 받지 않는다.

## 구조·호환성과 남은 범위

`20261117_0017`은 availability_profiles 테이블(user_id PK/FK, revision, weekly, exceptions,
updated_at)만 추가하며 이전 테이블·사용자 데이터를 바꾸지 않는다. 사용자별 기본값을 일괄 삽입하지 않는다.
이전 코드로 복구할 때 새 테이블·데이터를 유지하고 DB downgrade하지 않는다.
구버전도 저장된 계획 request를 파싱할 수 있도록 새 모드는 details에 저장한다. 새 시간 설정을 적용한
미승인 계획은 구버전의 snapshot 검증이 거절하므로 구버전에서 잘못 승인하지 않는다.

이 기능은 AI 역산 작업 후보·선후 관계·마감 위험도 API를 추가하지 않는다. 실제 빈 시간과 작업
순서를 반영한 위험도 계산은 다음 단계다. 중단 복구 PR #137을 기반으로 별도 PR에서 구현한다.
검사 범위는 계정 분리·동시 수정 감지·시간/날짜 검증·분리 구간·휴무/주말/자정 예외·기존 바쁨 일정·
승인 직전 변경 차단·길이와 가능 시간 검증·재승인 중복 방지·기존 수동 시간 요청 호환성이다.
PostgreSQL 검사는 명시적으로 허용된 임시 schema에서만 실행하고 운영 배포는 별도 기록한다.
