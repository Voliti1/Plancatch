# 공개 채용 공고 마감일 확대 검사와 보완

2026-11-12 공개 목록에서 고정 seed `20261112`로 사이트별 100개를 추출했다.
배포된 PR #133 `b3d1cc6` 코드를 별도 사본으로 고정해 실제 URL 추출을 실행한 뒤,
저장한 HTML 바이트를 수정 코드와 독립된 DOM/명시적 시간대 대조기로 다시 검사했다.
AI·개인 Google·사용자 DB를 사용하는 대량 검사는 아니다.

수정 전 오류 67개는 **잘못된 고정 날짜 제안 22개·정상 날짜 누락 45개**다.
수동 정상 144개는 상시/채용 시 마감 142개와 직무별 마감이 다른 2개다.
이를 실패나 자동 추출 성공으로 합산하지 않는다.

캐치 정상 후보 중 47개는 화면의 `24시`와 같은 공고 JSON-LD의 `23:59:59`가
보수적인 1초 차이로 표현된 사례다. 기존 정책대로 HTML의 초 단위 값은 보존하며
다음 날 `00:00`과 완전히 동일한 시각이었다고 주장하지 않는다.
시간대가 명시된 자소설 데이터는 동일 공고 ID와 함께 UTC→한국 시각 변환을 대조했다.
일부 서버 표시가 UTC라는 이유로 9시간 차이를 코드 오류로 잘못 세지 않는다.

## 수정 범위

- 잡코리아: 공개 헤드헌팅 공고의 전용 마감일 메타 설명을 읽는다. 대표 URL이
  제출 공고와 일치하고 알려진 본문 구조가 있어야 하며, 광고·회사 소개·iframe은 읽지 않는다.
- 잡코리아: 실제 접수 안내의 `채용 시 마감/상시채용`을 임시 타이머 날짜보다 우선한다.
  대표 URL이 없는 신형 화면은 기존 검증을 통과한 동일 공고 JobPosting으로만 소유를 증명한다.
  ID/대표 URL 충돌, 숨김/메뉴 영역, 복수 접수 안내·과도한 데이터는 그대로 거부한다.
- 잡코리아: HTML 스트리밍으로 화면 타이머 span이 아직 없더라도, 한 개의 전용
  남은 기간 데이터와 동일 공고 만료 시각이 일치하면 읽는다. 복수 타이머·불일치는 수동 확인이다.
- 캐치: `[11월]`·`[CATCH-UP]` 같은 실제 제목 앞부분을 회사 접두어로 잘못 제거하지 않는다.
  메타 제목의 회사 접두어 하나만 정규화하고, 본문 제목/ID/대표 URL을 계속 대조한다.
- 캐치: `채용예정 시작일 ~ 종료일 시각`의 종료일을 사용한다. 시작일·요일·시각이 잘못되거나
  기간이 역전된 경우 자동 확정하지 않는다. 연도는 같은 공고의 명시적 메타 날짜로 한정한다.
- 캐치: 화면에 날짜만 있더라도 같은 공고 HTML에 명시된 시각이 있으면 보존하고 출처를 안내한다.
  보이지 않는 시간을 임의로 자정으로 바꿔 실제 정오 마감을 놓치지 않는다.
- 공통: `채용시스템/채용 시작일`을 `채용 시 마감`으로 오인하지 않는다. 검증된 접수기간 필드는
  본문의 무관한 채용시 문구보다 우선하며, 연속 줄에서 상시/채용 시 마감으로 끝나는 기간도 인식한다.

## 검증과 범위 제한

- 최종 백엔드 전체 **1,057개 통과·선택 PostgreSQL 13개 제외**, Ruff·diff 공백 검사 통과.
  날짜 충돌/타 공고/숨김/추천 영역·변조·잘못된 날짜·반복 승인 중복 방지 회귀 검사를 포함한다.
- 원격 차단을 통과로 세지 않는다. 캐치 첫 요청 제한 뒤 최소 15분 대기하고
  10초 간격으로 이어 읽었으며, 이미 읽은 6개는 저장본을 재사용했다. 새 차단은 없었다.
- robots·SSRF·TLS·2MB 본문/시간/파싱 상한을 유지한다. 로그인·차단 우회,
  JS 실행·이미지 OCR fallback·새 의존성·DB 구조·프론트 변경은 없다.
- 이 표는 수집된 공개 목록 범위의 600개 저장 응답에 대한 결과다. 전 사이트의 무작위
  균등 표본이나 앞으로의 모든 공고/사이트 변경/외부 장애에 대한 무오류 보장이 아니다.
- 기존 저장 분석을 일괄 변경하지 않는다. 새 추출/분석에서 보완 로직이 적용되며,
  최종 등록은 기존대로 사용자의 검토·승인이 필요하다.

원본 목록/추출 시각/HTML gzip과 SHA256, 고정 코드, 전후 JSON·CSV 및 재검사 도구는
워크스페이스 `checkpoints/url-site-audit-100-20261112`와 날짜별 검사 스크립트에 별도 보관한다.
