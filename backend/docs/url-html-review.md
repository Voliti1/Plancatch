# URL HTML 날짜 검토

> 2026-10-27 변경: 날짜가 명확하고 시간만 없으면 한국 시간 23:59를 후보에 미리 입력하고 사용자 승인을 받습니다. 이전의 시간 누락 시 빈칸 유지 규칙은 [마감 시간 처리 정책](deadline-clock-policy.md)으로 대체합니다.

- 모든 URL 자료는 로컬 HTML/텍스트 추출값으로 검토한다. Gemini 자동 대체 호출 없음.
  텍스트 자료의 Gemini 분석·명시적 전송 동의·40,000자 제한은 유지한다.
- 사람인 첫 접수기간, 동일 공고의 검증된 JSON-LD JobPosting validThrough,
  첫 main/article의 마감·접수기간 문맥 순서로 날짜를 읽는다. 첫 공고 뒤의 article,
  aside 및 명시적인 추천/광고 컨테이너는 일반 날짜 선택에서 제외한다.
  알 수 없는 레이아웃의 일반 body 전체를 날짜 근거로 신뢰하지 않는다.
- 추출 시 제출/수집 URL·최대30개 날짜·짧은 근거·상시 모집 여부를 같은 원문 스냅샷에 보관한다.
  날짜 선택은 최대100자/근거500자, 전체 추출은 기존100,000자 한도다.
  기존 robots/DNS pinning/TLS/로그인·시간·응답 크기/이동 제한은 변경하지 않는다.
- 날짜·시간이 완전하고 시간대만 없으면 한국 시간. 명시 ISO 오프셋은 존중한다.
  연도/시간 누락·잘못된 날짜·여러 마감·접수기간 충돌은 임의 추측하지 않는다.
  선택지를 표시하되 불완전한 날짜는 사용자가 전체 일시를 입력해야 한다.
- 채용 시 마감/상시 모집은 기본 마감일 없음. 사용자가 원하는 일시를 직접 입력하고 승인한다.
- 날짜가 하나여도 URL auto-register는422이며 검토·승인 API만 실제 Deadline을 만든다.
  승인 중복 방지·소유권·revision·원문 hash 검사 유지. 안전 마감·Task·배치/Google 쓰기 없음.
- 과거 failed 분석의 GET에서도 읽힌 날짜를 제공한다. POST /api/ai-analyses/{id}/recover-html은
  본인 소유 failed URL만 허용하고 현재 원문 hash가 같아야 한다. 기존 실패 이력은 보존하며
  새 HTML 검토를 만들거나 동일 원문의 기존 processing/ready/approved HTML 검토를 재사용한다.
  재전송·외부 AI 호출 없음. 자료 변경은409, 다른 소유자404, 텍스트 자료422.
- 옛 사람인/동일 공고 구조화 스냅샷은 호환한다. 정보가 없는 옛 자료는 다시 추출하거나 수동 입력.
  이전 ready/approved 분석을 자동 수정하거나 사용자 자료를 일괄 재처리하지 않는다.
- 범용 사이트/무한 스크롤/CSS/JS 레이아웃 변경까지 정확성을 보장하지 않는다.
  불명확하면 자동 등록하지 않고 원문 확인·수동 입력으로 진행한다. 네트워크 차단 자체를 우회하지 않는다.
- DB migration·새 키·의존성 변경 없음. 화면·백엔드는 함께 배포해야 한다.
