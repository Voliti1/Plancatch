# 문장으로 일정 등록

새 일정 등록의 **문장으로 등록**에서 일정 하나를 입력하고 미리보기 → 내용 수정 → 등록으로 진행합니다.
원본 자료의 텍스트를 Gemini로 보내는 분석과 별개의 경로입니다. 외부 AI·링크 접속 없이 서버가 지원하는 한국어 표현을 읽습니다.

## 첫 버전의 표현과 기본값

- 오늘·내일·모레·글피·N일 후/뒤, 요일, 이번 주/다음 주/다다음 주 요일.
- 연·월·일, 점·슬래시·하이픈 날짜. 연도가 없으면 올해로 해석하고 안내합니다.
- 오전/오후·아침/저녁·밤/새벽·낮, 18:00, 18시30분, 3시 반, 정오/자정.
- `오후 3시부터 4시`, `18:00~19:30`, `1시간30분`, `한 시간`, `30분`.
- `마감·기한·제출·까지` 등을 마감일로 제안하고 시작/종료 범위가 있으면 할 일로 제안합니다. 사용자가 종류를 바꿀 수 있습니다.
- 종료가 없는 할 일은 **1시간**으로 제안합니다. 사용자 선택으로 확정한 기본값이며 수정 가능합니다.
- 날짜만 있는 마감일은 **23:59**로 제안합니다. 할 일의 시작 시각이나 빠진 날짜는 만들지 않습니다.

기준은 요청 시점 서버의 한국 시간입니다. 미리보기에 기준 시각과 보완할 내용을 표시합니다.
올해로 해석한 날짜나 ‘이번 주’가 이미 지났으면 과거 시각임을 안내하며 다음 해/주로 몰래 넘기지 않습니다.
자정은 해당 날짜 시작 00:00, 24시는 다음 날 00:00입니다. 밤에서 새벽으로 넘어가는 범위는 다음 날 종료로 해석합니다.

범용 AI 언어 이해나 모든 한국어 표현을 지원하는 기능은 아닙니다. 반복·여러 일정·다른 지역 시간,
날짜 누락·잘못된 시각·충돌은 자동 저장하지 않으며 확인 화면에서 직접 입력할 수 있습니다.
월말·휴일 계산, 음력, 복잡한 조건 문장, 초 단위 시각, 자연어 수정/삭제 명령은 후속 범위입니다.

## API와 저장

`POST /api/schedules/interpret`는 인증이 필요합니다. 요청은 `{"text":"내일 오후 3시 회의"}`이며1~1000자, 공백만/추가 필드는 거절합니다.
응답은 kind/task 또는 deadline, title, start_at/end_at(없으면 빈 값), reference_at, timezone, notices입니다.
시간은 시간대가 있는 ISO8601, timezone은 Asia/Seoul입니다. 사용자 문장/후보를 DB에 저장하거나 외부로 전송하지 않습니다.

미리보기만으로 원본 자료·마감일·할 일을 만들지 않습니다. 최종 등록은 기존 소유자 범위의
`POST /api/tasks`(고정 할 일) 또는 `POST /api/deadlines`(확인한 마감일) 계약을 재사용합니다.
이미 있는 읽기 전용 캘린더 등록 목록으로 표시되며 별도 일정 배치를 중복 생성하지 않습니다. Google 전송은 별도 사용자 확인입니다.
DB 구조·비밀·URL HTML/이미지 AI 정책은 바꾸지 않습니다.

화면은 해석 중 중복 요청/방식 전환, 저장 중 중복 제출을 막고 새 등록 진입 뒤 늦은 응답을 버립니다.
문장 변경 시 이전 미리보기를 지우고, 종류·제목·시간을 검토 후 등록하도록 합니다.

## 확인

합성 문장 검사와 로그인 필수/입력 경계/미리보기 무저장/기존 캘린더 투영 API 검사,
PC·모바일의 수정·등록·누락값 보완·오류·늦은 응답·키보드 이동을 검사합니다.
배포 검증은 임시 소유 계정만 사용하고 정리하며 사용자 데이터나 Google 일정을 수정하지 않습니다.
