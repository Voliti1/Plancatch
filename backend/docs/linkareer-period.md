# 링커리어 접수기간 추출·검토

단일 공개 `/activity/{공고번호}`의 접수기간을 읽고 기존 HTML 검토·수정·승인 API에
연결합니다. 사용자 승인 전에는 마감일을 만들지 않습니다.

## 근거와 날짜·시각 처리

2026-10-27 공고 `356174`를 기존 공개 추출 절차로 확인했습니다.

- 화면의 `접수기간` 항목은 시작일 `2026.10.12`, 마감일 `2026.10.31`입니다.
- 같은 HTML의 JobPosting `validThrough`는 `2026-10-31T14:59:59.999Z`입니다.
  한국 시간으로 `2026-10-31T23:59:59.999+09:00`이며 소수초까지 보존합니다.
- 화면에는 날짜만 있으므로, 메타데이터의 시각을 후보로 사용한다는 안내와 기업 원문
  확인 안내를 표시합니다. 사용자가 시각을 수정하고 승인할 수 있습니다.
  메타데이터가 없거나 날짜만 있는 경우에는 23:59/00:00을 임의로 넣지 않습니다.

같은 공고의 근거만 사용하기 위해 다음을 검증합니다.

1. 공식 `linkareer.com` / `www.linkareer.com` 숫자 공고 경로와 같은 출처·ID의 canonical.
2. 유일한 보이는 h1과 같은 제목의 JobPosting. 공고 제목은 본문 제외용 header 안에
   있어도 식별용으로만 읽습니다. 숨김·탐색·푸터 제목은 사용하지 않습니다.
3. `article`/`main` 안의 같은 dl에서 `접수기간` dt와 dd의 `start-at`·`end-at` 표시.
   일반 날짜·활동기간·추천 공고 데이터는 마감일로 취급하지 않습니다.
4. 시작일 ≤ 종료일이며 메타데이터 일시를 한국 시간으로 변환한 날짜가 표시 마감일과
   같아야 합니다. 화면에 시각도 있으면 분 단위로 대조합니다. 메타데이터의 초·소수초는
   보존하며, 시간대 없는 메타데이터 일시는 자동 확정하지 않습니다.

JobPosting의 URL이 없는 예외는 이 어댑터의 canonical·제목 대조에 한정합니다.
명시된 URL/@id/mainEntityOfPage가 다른 공고면 제외합니다. identifier의 사업자등록번호를
공고 ID로 오해하지 않습니다. 여러 접수기간·제목·상이한 메타데이터, 잘못된 날짜·기간은
경고와 함께 직접 확인 대상으로 남깁니다.

## 범위와 반영

기존 robots·공개 URL·응답/텍스트 크기 제한을 유지합니다. JavaScript 실행, 추가
API·iframe 요청, 로그인 우회·외부 AI 전송은 없습니다. JSON-LD는 기존 16블록·100,000자,
128노드·8단계 제한을 사용합니다. 화면 필드는 200자, 제목은 1,000자, 수집 항목은 각각
최대 8개로 제한하며 초과 시 자동 시각 확정을 차단합니다.

기존 `source_period.site`에 `linkareer`를 추가합니다. 화면에는 시작·마감 원문 날짜,
한국 시간 마감일, 현재 남은 기간을 표시합니다. 시각 미확정일 때는 확인된 날짜와 직접
입력 안내를 표시하며, 임의 시각을 입력란에 채우지 않습니다.

기존 수정 revision·원문 변경 검사·중복 승인 방지 API를 사용합니다. 새 API 경로,
환경변수, DB·배포 설정 변경은 없습니다. 백엔드·프론트엔드를 함께 반영해야 하며,
기존 자료는 재추출 후 새 검토가 필요합니다. 승인으로 Task·일정 블록·Google Calendar
이벤트를 생성하지 않습니다.

## 검증

`tests/test_linkareer_period.py`는 합성 HTML과 격리된 SQLite에서 제목/header 식별,
공고 범위·원문 날짜·메타데이터 대조, 시각 누락, 충돌·숨김·길이 제한, 수정·승인·재시도와
소수초 보존을 확인합니다. SQLite가 오프셋을 버리기 전 삽입 값도 확인합니다.
실제 URL은 robots/DNS/IP 고정 추출 절차로 읽기만 검증하며 사용자/RDS 데이터는 변경하지 않습니다.

`frontend/tests/linkareer-period.spec.ts`는 PC·모바일에서 메타데이터 안내·한국 시간·남은
기간, 제목 수정 후 밀리초 보존·승인·새로고침, 시각 누락 시 사용자 입력 및 충돌 처리를
검사합니다. 브라우저 가상 응답은 테스트에만 존재합니다.
