# 잡플래닛 HTML 마감 날짜 검토

> 2026-10-27 변경: 날짜가 명확하고 시간만 없으면 한국 시간 23:59를 후보에 미리 입력하고 사용자 승인을 받습니다. 이전의 시간 누락 시 빈칸 유지 규칙은 [마감 시간 처리 정책](deadline-clock-policy.md)으로 대체합니다.

단일 잡플래닛 채용공고의 `<dt>마감일</dt>`에 대응하는 `<dd>`를 읽어 기존 HTML
검토·수정·승인 흐름으로 연결합니다. 날짜만 있으면 사용자에게 마감 시각을 입력받습니다.

## 식별·추출

- 공식 `jobplanet.co.kr` / `www.jobplanet.co.kr`의 `/job/search` 경로이며
  `posting_ids[]`가 숫자 하나일 때만 적용합니다. 일반 검색, 여러 공고 ID, 중복·모호한
  ID 매개변수는 처리하지 않습니다. `entry` 같은 추적 값과 무관하게 canonical의
  동일 공고 ID·출처를 확인합니다.
- `main` 또는 `article` 안의 유일한 `h1`과 마감일 항목을 확인합니다. 같은 `dl` 행의
  `dt`/`dd` 쌍만 읽으며 숨김·탐색·스크립트 요소는 제외합니다. 여러 제목·마감일 항목,
  canonical 누락·불일치, 날짜와 `~11/25(수)`의 월·일·요일 충돌은 직접 확인 대상으로
  남깁니다. 일반 날짜, 다른 필드의 날짜, 추천 공고나 iframe 내용은 사용하지 않습니다.
- 표시 날짜는 `YYYY.MM.DD`로 읽고, 해당 필드에 시간이 명시된 경우에만 기존 한국 시간
  정책으로 전체 마감 일시를 만듭니다. 날짜만 있으면 `due_at: null`, `selected: false`입니다.
  원문을 확인한 사용자가 날짜·시간을 입력하고 선택·저장한 뒤 승인해야 합니다.
- 검색 데이터의 정규화된 `end_at`/`end_at_factor`나 메타 설명으로 시간을 보충하지
  않습니다. 날짜만 표시한 공고에 00:00이나 23:59:59를 임의로 넣지 않습니다.
- 기존 2 MB 응답·100,000자 추출 제한을 유지합니다. 화면 필드는 300자, 제목은
  1,000자, 수집 항목은 각각 최대 8개이며 초과하면 자동 일시를 확정하지 않습니다.
  JavaScript 실행, 로그인, 추가 API/iframe 요청, 외부 AI 전송은 없습니다.

2026-10-27 사용자 제공 공고 `1776386`의 일반 공개 HTTPS 응답에서
`2026.11.25`와 `~11/25(수)`를 확인했습니다. 직접 받은 HTML을 파싱하면 날짜
`2026-11-25`만 확인되고 마감 시각은 비워집니다.

## 현재 실제 수집 제한

같은 URL을 프로젝트의 기존 DNS 검증·IP 고정 전송 경로로 요청하면 이 환경에서는
Cloudflare 서버의 HTTP 403을 받았습니다. 따라서 해당 경로의 실제 URL 등록부터 승인까지는
검증 완료로 간주할 수 없습니다. 일반 HTTPS 읽기와 기존 서버 수집 경로 검증은 구분합니다.

전송·robots·접근 정책은 변경하지 않았습니다. 403은 기존 `access_denied`로 유지하고
화면에 접근 차단 및 공개 URL/허용된 텍스트 등록 안내를 표시합니다. 분석이나 가짜 마감일을
생성하지 않습니다. 수집이 허용되는 운영 환경에서 실제 URL 흐름을 별도로 확인해야 합니다.

## 응답·화면·반영

기존 `source_period.site`에 `jobplanet`을 추가합니다. 원문 날짜와 날짜 전용 선택지를
보여주고, 후보에 확정된 날짜가 있으면 마감 시각을 직접 입력하도록 안내합니다.
날짜만 있는 선택지를 눌러도 날짜·시간 입력란에 임의 시각을 넣지 않습니다.
수정·승인·revision·원문 변경 검사 및 중복 승인 방지는 기존 API를 사용합니다.
새 API 경로·환경변수·DB 변경은 없습니다. 백엔드와 프론트엔드 코드가 모두 필요합니다.

기존 저장 자료·분석은 자동으로 바꾸지 않습니다. 접근이 허용되면 재추출과 새 검토로
적용합니다. 승인으로 Task·일정 블록·Google Calendar 이벤트를 생성하지 않습니다.

## 검증

`tests/test_jobplanet_period.py`는 합성 HTML과 격리된 SQLite로 ID·행 범위·날짜·요일,
누락 시각, 숨김·잘못된 공고 배제, 명시된 시각, 충돌·길이 제한·403 보존, 사용자 시간
입력 후 수정·승인·재조회·중복 승인을 확인합니다. RDS와 실제 계정은 사용하지 않습니다.

`frontend/tests/jobplanet-period.spec.ts`는 PC·모바일에서 날짜 전용 안내, 임의 시각
미입력, 사용자 시간 저장·승인·새로고침, 충돌 및 접근 거부 안내를 확인합니다.
가상 응답은 테스트에서만 사용하며 운영 코드에는 가짜 결과가 없습니다.
