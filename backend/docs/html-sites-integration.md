# 사이트별 HTML 마감일 추출 통합

2026-10-27 운영 최적화 브랜치(#67)와 사이트별 추출 브랜치를 통합한다.
작업 이력은 #60 잡코리아 → #62 캐치 → #63 잡플래닛 → #65 자소설닷컴 → #66 링커리어다.
main 병합과 운영 배포는 별도 절차이며 이 문서 자체는 배포 완료 증거가 아니다.

## 동작

- 기존 사람인 및 일반 공개 HTML 추출을 유지한다. 사이트별 접수기간과 동일 공고 데이터를 대조한다.
- URL 경로는 Gemini 없이 HTML과 포함된 구조화 데이터를 읽는다. 검토 후 승인해야 마감일이 생성된다.
- 시각 누락·날짜 충돌·채용 시 마감은 시각을 임의로 확정하지 않고 사용자가 확인·입력한다.
- 링커리어는 화면 날짜와 동일 공고 메타데이터의 시각을 대조한다. 날짜만 보이는 경우 시각의 출처를
  안내하며 한국 시간 표시·소수 초를 포함한 원래 시점을 수정/승인/재조회에서도 보존한다.
- 자소설닷컴은 HTML 표시 필드를 시간대 없는 비교용 튜플로 다룬다. 동일 공고의 시작·종료 데이터가
  모두 UTC 또는 모두 한국 시간으로 표시된 경우만 일치로 인정한다. HTML 자체에 시간대를 가정하지 않는다.
- 네트워크 제한·robots·호스트/공고 식별 검증·크기 제한을 유지한다. 로그인/403 차단을 우회하지 않는다.

## 점검 결과와 알려진 제한

- 통합 후보의 공개 공고 각1개: 사람인·잡코리아·캐치·자소설닷컴·링커리어 추출 성공.
- 잡플래닛은 실제 서버의 HTTP403으로 수집이 거부됐다. 합성 HTML 파서/검토 검사는 통과하지만
  해당 사이트의 실제 URL 수집이 보장되지는 않는다. 접근 차단 시 오류를 안내하며 결과를 꾸며내지 않는다.
  사용자는 텍스트나 이미지 입력을 사용할 수 있다.
- 관련 PC/모바일54개 검사와 frontend lint/typecheck/build 통과. 브라우저 검사는 가상 API를 사용한다.
- backend import 순서13건·문자열 결합5건을 정리하고 비교용 datetime1건을 필드 비교로 변경했다.
  백엔드 검사는 backend 폴더에서 `python -m ruff check app tests`, `python -m pytest -q`로 실행한다.
- 사이트별1개 표본 검사는 모든 공고나 이후 사이트 구조 변경을 보장하지 않는다.

## 배포/복구 조건

- 기존 #67의 응답 EOF 처리·DB 연결/잠금 개선·캘린더 조회/취소·이미지 형식/메모리 개선을 유지한다.
- DB 모델/마이그레이션·의존성·비밀·환경·HTTPS·Google 설정 변경 없음.
- 배포 전 정확한 이전 코드와 실행 빌드를 보존하고 진행 중 추출/분석이 없는지 확인한다.
- 복구는 이전 코드/빌드만 되돌리고 DB0008·사용자 데이터·원본 이미지·최신 환경/HTTPS는 유지한다.
- 실제 배포 커밋/빌드/복구 위치/검증 결과는 프로젝트 checkpoints/current-deployment.md에 기록한다.
