# 중단된 원문 추출·분석 복구

서버가 중간에 꺼져도 자료가 영구적으로 ‘처리 중’에 머물지 않도록 한다.
기존 Source/Analysis 상태 저장에 실행별 소유권과 유효 시간을 추가한다.

- 시작 요청을 저장할 때 새 UUID와 120초 유효 시간을 함께 저장한다.
- 원문 추출·텍스트/HTML 분석·이미지/PDF 분석 작업은 20초마다 짧은 DB 거래로 유효 시간을 갱신한다.
  외부 페이지/AI 요청 동안 DB 연결이나 행 잠금을 계속 잡고 있지 않는다.
- 서버 시작 및 실행 중 10초 간격으로 만료된 작업을 최대 50개씩 찾는다.
  다른 서버/프로세스에서 정상 갱신 중인 작업은 유지한다. 기존 버전의 실행 기록은
  갱신 시간이 없으므로 마지막 변경 후 15분의 여유를 둔다.
- 만료된 작업은 기존 실패 상태와 `processing_interrupted` 사유로 저장한다.
  파일 분석의 자료/분석 상태는 함께 해제한다. 원문·업로드 파일·후보 이력·등록한 일정은 지우지 않는다.
- 종료가 늦은 이전 실행은 UUID·상태·유효 시간이 모두 맞을 때만 결과를 저장한다.
  복구 후 시작한 새 실행의 결과를 이전 응답으로 덮어쓰지 않는다.
- 복구는 자동 분석 재실행이 아니다. 웹 요청·Gemini 전송·일정 생성·승인·Google 전송을 하지 않는다.
  다시 추출/분석하는 것은 사용자의 명시적 화면 진입·요청으로 시작한다.
  텍스트·이미지 외부 분석의 기존 전송 동의와 파일 해시 검증을 유지한다.

화면은 ‘서버 작업이 중단되었습니다. 저장한 자료는 유지됩니다’라고 안내한다.
중단된 URL/텍스트 검토는 이전 실패 화면을 계속 재사용하지 않고 새 검토를 만들 수 있다.
정상·승인된 기존 검토의 재사용과 재승인 중복 방지는 유지한다.
파일은 기존 재분석 흐름으로 다시 요청하며 이전 실패 기록을 보존한다.

서비스에 새 cron/프로세스/외부 의존성을 추가하지 않는다. 기존 앱 수명 주기에 복구 검사를 연결하며
DB를 교체하는 API 단위 검사에서는 실제 운영 복구 작업을 시작하지 않는다.
DB 장애가 있으면 임의로 완료/실패 처리하지 않고 다음 검사 때 다시 확인한다.
로그에는 원문·파일·키·공급자 응답을 남기지 않고 복구 개수와 오류 종류만 기록한다.

## DB 구조와 복구

`20261117_0016`은 sources/analyses 각각에 nullable `processing_run_id`·`processing_lease_until`과
처리 중인 행용 인덱스만 추가한다. 기존 사용자 데이터·상태를 migration에서 일괄 변경하지 않는다.
운영 적용 전 DB 구조만 백업하고 이전 코드/화면 복구 경로를 보관한다.
오래된 코드와도 추가 필드는 호환되지만 오래된 코드로 돌아가면 중단 복구가 실행되지 않는다.
운영 복구에서 DB downgrade나 사용자 데이터 덮어쓰기를 하지 않는다.

합성 검사 범위: 만료/정상/기존 작업, 파일과 분석 동시 복구, 여러 작업의 제한된 처리,
이전 실행의 늦은 응답 차단, 실제 앱 시작 검사, 명시적 URL 재검토·정상 결과 재사용,
브라우저의 URL 재시도와 텍스트 재동의, 일회성 DB의 nullable migration/기존 행 보존.
운영 PostgreSQL의 잠금/구조 변경 및 실제 서버 적용 검증은 별도 배포 기록으로 구분한다.
