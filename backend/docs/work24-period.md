# 고용24 공개 공고 접수 마감일

고용24 인증 공고의 공개 HTML에서 `접수 마감일`을 읽고 기존 HTML 검토·수정·승인
흐름으로 연결합니다. 사용자 승인 전에는 실제 마감일을 만들지 않습니다.

## 원문과 24:00

2026-10-27 공고 `K150122610270007`을 기존 robots/DNS/IP 고정 수집 절차로 확인했습니다.
원문은 `2026.11.10 (화) 24:00`이며, 등록 일시는 한국 시간
`2026-11-11T00:00:00+09:00`(UTC `2026-11-10T15:00:00Z`)입니다.

- 원문 표기는 그대로 보존하고, 화면에 `24:00 = 다음 날 00:00`을 안내합니다.
- `24:00`만 다음 날로 바꿉니다. `24:01`, `25:00`, 잘못된 날짜·요일은 확정하지 않습니다.
  월말·연말·윤일 경계도 검사하며 날짜 범위 초과는 거부합니다.
- 시각이 없거나 채용 시 마감이면 원하는 날짜·시각을 직접 입력하도록 남깁니다.
  D-day나 현재 시간을 이용해 마감일을 만들지 않습니다.
- 원문에 시간대가 없으므로 기존 서비스 정책인 한국 시간 기본값을 기록합니다.

## 공개 공고와 닫힌 계정 관리 팝업

고용24 페이지 하단에는 비밀번호 추가·재확인·변경 팝업이 함께 포함됩니다.
공식 `cm/static/css/common.css`의 `.full_pop`은 기본 숨김 상태이며 해당 기능을
열 때 표시 상태가 바뀝니다. 일반 추출기는 이 입력창을 로그인 필요 화면으로 감지했습니다.

고용24 전용 파서는 다음 공개 공고 증거를 먼저 모두 확인합니다.

1. 공식 고용24 호스트의 `/wk/a/b/1500/empDetailAuthView.do`, 유일한 K+15자리 숫자 또는 KF/KJ 등 K+영문1자+숫자14자리
   `wantedAuthNo`, `infoTypeCd=VALIDATION`, `infoTypeGroup=tb_workinfoworknet`.
2. `moveForm`의 같은 출처·공고 ID action과 숨김 `wantedAuthNo` 입력 값.
3. 보이는 구인인증번호 표의 같은 ID, 유일한 `emp_colbox_div` 접수 마감일.

증거가 일치한 뒤에만 `footer#footer` 안의 `form#pwdCfrmForm000`에 속하는 알려진 계정 관리
팝업 3종(`chkPwdCfrmYn`, `chkPwdCfrmYnAdd`, `chkPwdCfrmYnChg`)을 닫힌 요소로 처리합니다.
클래스가 정확히 `full_pop large full_01`이며 별도의 표시 상태가 없어야 합니다.
팝업 내용·비밀번호 값은 추출 결과에 포함하지 않습니다.

`display:block`, `aria-hidden=false`, 열린 상태, 추가 클래스, 알 수 없는 팝업이나 위치,
공고 ID 불일치에는 이 예외를 적용하지 않습니다. 본문 등 다른 위치의 비밀번호 입력은
기존 로그인 차단을 유지합니다. 감지한 password_form 플래그를 지우거나 인증 요청을
우회하지 않습니다. 다른 사이트에는 일반 추출기를 그대로 사용합니다.

이 규칙은 확인한 공개 페이지 구조와 기본 숨김 스타일에 한정됩니다. 알 수 없는 구조·HTML
표시 상태는 기본 로그인 차단을 유지하며, 사이트 CSS 규칙이 바뀌면 이 예외의 재검증이
필요합니다. CSS/JS를 실행·추가 요청하지 않습니다.
날짜·라벨은 200자, 인증번호 표 라벨은 1,500자·값 100자, 수집 항목은 각각 8개로 제한합니다.

## API·화면·반영

기존 `source_period.site`에 `work24`를 추가합니다. 화면에 원문 마감일, 한국 시간
등록 일시와 남은 기간을 표시합니다. 수정·승인·revision·원문 변경 검사·중복 승인 방지는
기존 API를 사용합니다. 새 경로·환경변수·의존성·DB·배포 설정 변경은 없습니다.
작업 생성·일정 배치·Google Calendar 이벤트 생성은 수행하지 않습니다.

최신 `integration/html-deadline-sites`의 이미지 형식·메모리·읽기 처리 개선을 보존해
추가했습니다. 백엔드와 프론트엔드 코드가 모두 필요하며 운영 배포는 별도입니다.
기존 자료는 다시 추출하고 새 검토를 시작해야 합니다.

2026-10-27 통합에서는 이후 운영 #69의 캐치24시·기업명 추출도 유지했습니다.
고용24 기업명은 공고 인증번호 검증 후 `div.emp_sumup_wrp p.corp_info > strong`에서 읽어
URL 검토 스냅샷의 `company_name`으로 저장합니다. 다른 영역의 회사명을 끌어오지 않으며
현재 지원 범위는 공개 인증 채용공고(VALIDATION/tb_workinfoworknet)입니다.
마감된 공고의 안내문, 검색 결과, 계정 관리·지원 신청 화면을 채용공고로 취급하지 않습니다.
공식 common.css의 `.full_pop { display:none }` 기본 규칙을 공개 읽기로 다시 확인했습니다.

배포 후 기존 캐치 회귀 검사에서 p.t1 안에 홍보 링크가 추가되는 실제 응답을 발견했습니다.
캐치 날짜는 p.t1의 첫 번째 직접 자식 span을 읽되 내부/옆의 링크·버튼 문구를 제외하도록 보완했습니다.

## 검증

`tests/test_work24_period.py`는 합성 HTML과 격리된 SQLite에서 24:00·연말·윤일,
시각 누락·충돌, 공고 식별, 닫힌 팝업 내용 제외, 실제 로그인 차단 유지, 승인·중복 승인을
검증합니다. DB 삽입 직전 오프셋도 확인합니다. 실제 URL 검증은 공개 읽기만 수행합니다.

`frontend/tests/work24-period.spec.ts`는 PC·모바일에서 원문 24:00과 다음 날 00:00 표시,
수정·승인·새로고침, 시각 누락·충돌 안내를 확인합니다. 가상 응답은 테스트에서만 사용합니다.

2026-10-27 검증 환경에서 백엔드 전체 591개 통과·PostgreSQL 별도 실행 7개 제외,
고용24 변경 파일의 Ruff 검사는 통과했습니다. Ruff 0.17.3 전체 검사에는 기존
security·Google 이벤트/내보내기·자소설닷컴·사람인 테스트 파일의 UP017/FURB162
진단 7건이 남아 있습니다. 해당 파일들은 이번 작업에서 변경하지 않았습니다.
