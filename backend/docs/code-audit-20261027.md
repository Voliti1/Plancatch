# 현재 운영 코드 점검과 조회 경로 최적화

기준은 이미지 형식 확장 PR #64의 `1b6c543`이다. 앱 기능 소스 157개 파일(539,461바이트),
파이썬 모듈 57개, HTTP 처리 함수 45개의 구조를 확인하고 백엔드 전체 검사와 프론트엔드
타입·lint·빌드·PC/모바일 회귀 검사로 기존 연결을 확인했다. 배포 커밋·최종 검사 수·복구 경로는
작업 폴더의 `checkpoints/PRS.md`, `current-deployment.md`, `RESUME.md`와 해당 PR을 따른다.

## 확인하고 수정한 문제

- AI 응답: 실제 `http.client.HTTPResponse`로 재현했을 때 Content-Length 본문을 정상적으로
  끝까지 읽은 뒤 `fp=None`인 연결을 다시 접근하여 실패했다. 닫힘 여부를 확인하고, 선언된 길이보다
  일찍 끊긴 응답도 거부한다. 정상 길이·chunked·빈 응답·중간 끊김·용량 제한을 외부 호출 없이 검사한다.
  이 수정은 과거 모든 AI 오류의 원인이 같았다는 뜻이 아니며, 자동 재전송을 추가하지 않는다.
- 원문 추출: 원격 페이지를 받는 동안 DB 연결을 계속 점유했다. 입력 값을 읽고 연결을 반환한 뒤
  외부 요청을 수행하고, 결과 저장 직전에만 다시 잠근다. 입력/상태가 변경되면 이전 결과로 덮어쓰지 않는다.
  연결이 하나뿐인 검사 DB에서 다운로드 중 다른 조회가 가능한지 재현 검사했다.
- 자료·이미지·분석 조회: 읽기에도 수정용 행 잠금을 사용했다. GET 상세·미리 보기·분석 이력에서는
  이를 해제하되, 등록·수정·삭제·승인의 기존 잠금과 소유권 검사를 유지한다.
- 캘린더 조회: 필요한 ID·제목·일시·표시 상태 열만 읽는다. 전체 메모/원문과 ORM 객체를 가져오지 않아도
  기존 응답, 기간 중첩, 소유권, 종류별 한도, 취소 배치의 중복 제외 규칙은 같다.
- 날짜 범위: 작업의 UTC 변환이나 일정 배치의 UTC 변환에서 표현 범위를 벗어나면 서버 예외가 발생했다.
  422 입력 오류로 처리하고 기존 작업·배치 내용은 그대로 유지한다.
- 이미지: 불투명 이미지에는 불필요한 RGBA 복사와 알파 마스크를 만들지 않는다. 투명 이미지는 기존처럼
  흰 배경으로 합성한다. 서버 Pillow13에서 합성 600만 화소 RGB 이미지, 매번 새 프로세스로 각 3회 측정:
  최대 메모리 중앙값 121,936→92,908KiB(약24% 감소), 변환 시간 중앙값 0.380→0.307초.
  두 경로의 최종 PNG 바이트 해시가 동일했다. 이 수치는 해당 합성 이미지의 측정 결과다.

## 프론트엔드 연결

- 같은 월간/주간 조회 범위에서 날짜만 선택하면 로컬 배치·등록 일정·Google 일정을 다시 조회하지 않는다.
  표시용 목록 계산도 데이터나 표시 범위가 바뀔 때 재사용한다. 기간 이동·명시적 새로고침은 새로 조회한다.
- 캘린더·목록 검색·마감일 선택 목록은 이탈/조건 변경 시 이전 조회를 취소한다. 페이지를 순회하는
  조회도 취소 뒤 다음 페이지 요청을 중단한다. 이미 시작된 서버 AI 작업을 취소하는 기능은 아니다.
- 취소 신호를 전달하면 기본 네트워크 제한 시간이 사라지던 공통 통신 함수를 수정했다.
  기본15초, Google 조회30초, 명시적 Google 전송60초를 유지한다.
- 한국 시간 표시 형식을 매번 새로 만들지 않고 재사용한다. 날짜 문자열이나 시간대 기준은 바꾸지 않는다.
- 오래된 두 브라우저 검사 파일이 이전 PDF 임시 선택창을 찾고 있었다. 현재 이미지 입력과 유효한 PNG로
  바꾸되 초안 유지·새 등록 초기화·서식 검증은 그대로 검사한다.

## 보존 범위와 별도 작업

DB 구조·의존성·환경 비밀·HTTPS/nginx·Google 설정·사용자 데이터는 변경하지 않는다.
URL HTML 추출의 접근 정책, 이미지/텍스트 전송 동의, 삭제 보호, 검토 revision, 중복 승인/Google 전송 방지를 유지한다.
사람의 실제 캡처 재전송이나 실제 Google 일정 변경 없이 합성 자료·가상 외부 응답으로 회귀 검사한다.
PostgreSQL 구조 검사는 트랜잭션 안의 임시 스키마만 만들고 되돌린다.

현재 앱 소스는 약527KiB이며 운영 설치 폴더는 Python 환경232MiB, Node 라이브러리484MiB,
실행 빌드88MiB로 별개다. 배포 패키지 분리나 복구 사본 정리는 이번 코드 수정에 포함하지 않는다.
팀원 PR #60/#62/#63/#65는 별도 브랜치의 미배포 기능이며 이번 최적화로 자동 통합하거나 main에 병합하지 않는다.
이 점검은 현재 구현의 회귀 검증이며, 외부 사이트의 향후 HTML 변경이나 외부 서비스의 모든 실패를 보장하지 않는다.
