# 반복 할 일

시작·종료 시간이 있는 고정 할 일은 매일·매주·매월 반복할 수 있습니다. 기존 할 일에 nullable JSON `recurrence` 필드 하나를 추가합니다(변경 이력 `20261110_0013`). 기존 일정의 값은 비어 있으며 자동 전송이나 반복 변환을 하지 않습니다.

`POST /api/tasks`, `PATCH /api/tasks/{id}` 예시:

```json
{"recurrence":{"frequency":"weekly","interval":2,"count":5,"until":null}}
```

`interval`은 1~99, `count`는 첫 일정을 포함한 1~1000회입니다. `count`와 `until`은 동시에 지정할 수 없습니다. 둘 다 없으면 종료일이 없습니다. `until`은 한국 날짜를 포함하며 첫 일정 날짜보다 빠를 수 없습니다. 반복 해제는 `recurrence: null`입니다.

- 매주는 첫 일정의 요일, 매월은 첫 일정의 일자를 사용합니다. 31일이 없는 달이나 윤일이 없는 해는 건너뛰며 건너뛴 날짜는 횟수에 포함하지 않습니다.
- 캘린더 조회 범위에 겹치는 회차만 계산합니다. 각 회차의 수정 링크는 같은 할 일을 가리키며 DB에 복제 행을 만들지 않습니다. 조회 건수 제한과 `has_more`를 유지합니다.
- 수정·삭제는 전체 반복에 적용됩니다. 개별 회차 예외와 ‘이번 이후’ 수정은 아직 지원하지 않습니다. 배치가 있는 할 일과 반복 할 일을 중복으로 만들 수 없습니다.
- Google에는 같은 연결·동일한 전송 식별자로 반복 일정 원본 하나를 전송합니다. 자동 수정·삭제도 그 원본에 적용합니다. 출처·제목·시간·반복 규칙·ETag 검증과 기존 복구 가능한 재시도를 유지합니다. 반복 해제 시 Google의 반복 필드를 비웁니다.
- Google의 정상 회차는 로컬 회차와 시간·제목이 같은 경우만 중복 표시를 숨깁니다. 외부에서 바뀐 회차는 숨기지 않습니다.
- 문장 입력은 ‘매일’, ‘매주’, ‘격주’, ‘매월’을 인식하고 반복 할 일로 제안합니다. 종료 시간이 없으면 60분을 제안하며 저장 전 주기·날짜·시간을 수정할 수 있습니다. 매년·복잡한 복수 요일 규칙은 직접 단순 주기로 정리해야 합니다.

배포는 구조만 백업한 뒤 nullable 필드를 추가합니다. 실패 시 이전 코드와 화면을 복구하고 추가 필드는 유지합니다. 사용자 데이터 복원이나 자동 DB 다운그레이드는 하지 않습니다.
