# 반복 할 일

시작·종료 시간이 있는 고정 할 일은 매일·매주·매월 반복할 수 있습니다. 기존 할 일에 nullable JSON `recurrence` 필드 하나를 추가합니다(변경 이력 `20261110_0013`). 기존 일정의 값은 비어 있으며 자동 전송이나 반복 변환을 하지 않습니다.

`POST /api/tasks`, `PATCH /api/tasks/{id}` 예시:

```json
{"recurrence":{"frequency":"weekly","interval":2,"count":5,"until":null}}
```

`interval`은 1~99, `count`는 첫 일정을 포함한 1~1000회입니다. `count`와 `until`은 동시에 지정할 수 없습니다. 둘 다 없으면 종료일이 없습니다. `until`은 한국 날짜를 포함하며 첫 일정 날짜보다 빠를 수 없습니다. 반복 해제는 `recurrence: null`입니다.

- 매주는 첫 일정의 요일, 매월은 첫 일정의 일자를 사용합니다. 31일이 없는 달이나 윤일이 없는 해는 건너뛰며 건너뛴 날짜는 횟수에 포함하지 않습니다.
- 캘린더 조회 범위에 겹치는 회차만 계산합니다. 날짜별 링크는 `?occurrence=원래시작시각`으로 해당 회차를 구분합니다. 일반 회차의 복제 행은 만들지 않고, 개별 수정한 회차에만 연결된 고정 할 일 한 개를 저장합니다. 조회 건수 제한과 `has_more`를 유지합니다.
- `GET/PATCH/DELETE /api/tasks/{id}/occurrences?original_start=시간대가있는시각`으로 이번 회차만 조회·수정·삭제합니다. 원래 반복에서 실제 생성되는 시작 시각만 허용하며 소유권과 계정 잠금을 먼저 확인합니다. 같은 수정 재시도는 동일한 연결 행을 갱신하며 삭제 재시도는 원래 회차를 다시 만들지 않습니다. 원본의 `excluded_starts`에 제외 시각을 기록하고 수정 행에는 `series_id`, `original_start`를 저장합니다(변경 이력 `20261110_0014`). 개별 변경·삭제는 반복당 1,000회까지입니다. COUNT는 제외 전 원래 회차 수를 뜻하므로 개별 삭제로 반복 종료가 연장되지 않습니다.
- 전체 수정·삭제는 기존 할 일 API입니다. 전체 삭제는 개별 수정 행과 Google 전송 기록의 삭제 요청도 함께 처리합니다. 종료일·횟수 변경은 유효한 개별 변경을 유지하고 범위 밖 것은 제외합니다. 시작·종료 시각이나 주기를 바꿀 때 개별 예외가 있다면 `reset_occurrences: true`라는 명시적 초기화 허용이 필요하며 없으면 409입니다. 초기화는 개별 수정·삭제를 취소하고 전체 반복 설정으로 되돌립니다. ‘이번 이후’ 분할은 지원하지 않습니다.
- Google에는 같은 연결·동일한 전송 식별자로 반복 일정 원본 하나를 전송합니다. 자동 수정·삭제도 그 원본에 적용합니다. 출처·제목·시간·반복 규칙·ETag 검증과 기존 복구 가능한 재시도를 유지합니다. 반복 해제 시 Google의 반복 필드를 비웁니다.
- Google의 정상 회차는 로컬 회차와 시간·제목이 같은 경우만 중복 표시를 숨깁니다. 외부에서 바뀐 회차는 숨기지 않습니다.
- Google에는 제외 회차를 EXDATE로 전송하고 개별 수정 행은 기존 단일 할 일 전송 방식으로 반영합니다. 정상 원본·개별 수정의 식별자는 재시도에서도 유지합니다. EXDATE 순서·중복·UTC/한국 시간 표현 차이는 비교하되 실제 제외 날짜가 다르면 출처/ETag 보호를 유지해 충돌 처리합니다. 형식 근거는 [Google 반복 규칙 문서](https://developers.google.com/workspace/calendar/api/concepts/events-calendars#recurrence_rule)입니다.
- 문장 입력은 ‘매일’, ‘매주’, ‘격주’, ‘매월’과 ‘이번 달만’, ‘11월 25일까지’를 인식합니다. 화면의 ‘이번 달까지만’은 한국 시간의 현재 달 말일로 설정하며 날짜 지정으로 수정할 수 있습니다. 종료 시간이 없으면 60분을 제안하며 저장 전 주기·날짜·시간을 수정할 수 있습니다. 매년·복잡한 복수 요일 규칙은 직접 단순 주기로 정리해야 합니다.

배포는 구조만 백업한 뒤 nullable 필드·자기 참조 FK·유일성 제약을 추가합니다. 사용자 데이터 복원이나 자동 DB 다운그레이드는 하지 않습니다. **개별 변경 사용 후 예외를 모르는 #120 이전 백엔드로 단순 복구하면 제외 날짜가 다시 나타날 수 있습니다.** 이때는 예외 처리를 유지한 백엔드와 이전 프론트 빌드를 함께 사용해 화면만 복구해야 합니다. 전체 코드 복구는 예외 행·제외 기록이 없는지 확인한 경우에만 사용합니다.
