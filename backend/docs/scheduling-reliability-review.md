# 일정 검증 및 조회 비용 보완

2026-11-17 main의 인증·계정 분리, URL/파일 추출, 비동기 처리 복구, Google 동기화,
일정·반복·작업 순서·시간 추천과 프론트 요청/폴링 흐름을 점검하고 전체 회귀 검사를 수행했다.
모든 외부 사이트/개인 Google 계정/운영 데이터를 실제로 전송해 검사했다는 의미는 아니다.

## 재현해 수정한 동작

- 기존 선행 작업의 예약은 총 소요시간과 작업 순서만 확인했다. 이제 작업의 시작 가능 시각,
  완료 기한과 연결된 공식/안전 마감 안에 전부 들어가야 후행 작업의 선행 예약으로 인정한다.
  같은 계정에서 연결된 마감일을 확인할 수 없는 경우에도 인정하지 않는다.
- 선택하지 않은 선행 작업의 연결 마감일도 추천 생성 당시 상태에 포함한다. 추천을 만든 뒤
  그 마감일이 바뀌면 이전 추천의 승인을 거절하며 일부 일정만 저장하지 않는다.
  이미 완료한 선행 작업은 기존 완료 표시를 계속 사용한다. 기존 일정을 자동으로 옮기지 않는다.
- 반복 일정의 회차 존재 여부는 짧은 시간 구간으로 확인했지만 실제 종료 시각을 더하면
  날짜 범위를 넘을 수 있었다. 이제 실제 종료 시각과 한국 시간 표시 가능 여부까지 확인한다.
  읽기·수정·삭제 모두 표시 불가능한 날짜는 422로 거절하며 원본과 제외일을 바꾸지 않는다.

## 최적화와 유지 조건

- 최대 20개 선행 작업의 소유권/유형을 한 번에 조회한다. 20개 연결 저장 시 SELECT가
  기존 25회에서 최대 6회로 줄고, 작업/마감 설명·동기화 오류 본문은 판단에 사용하지 않으므로
  읽지 않는다. 선행 상태 계산도 마감일을 한 번에 조회하며 최대 4회 SELECT 검사로 보호한다.
- 작업별 기존 배치를 먼저 묶어 두어 각 작업마다 전체 배치를 다시 검색하지 않는다.
  위상 정렬 준비 단계의 작업 ID 집합도 한 번만 만든다. 정렬 전체를 선형 알고리즘으로
  바꿨다는 의미는 아니며, 기존의 우선순위와 결정 순서는 유지한다.
- 사용자 잠금, 소유권/순환/유형/중복/개수/오래된 수정 번호 검증은 그대로 유지한다.
  DB 구조·인덱스·외부 전송 정책·API 필드·화면 변경은 없다.

## 검증과 호환성

수정 전 코드에서 가능 기간/공식·안전 기한 위반, 선행 마감 변경 뒤 잘못된 승인,
20개 작업의 반복 조회, 범위 밖 반복 회차 요청을 재현했다. 수정 후 위 문제 외에도
타 계정·고정 작업·자기 연결·순환 거절, 기간 수정 후 추천 재개, 마지막 표시 가능 회차,
미리보기/승인 실패 시 기존 일정 불변을 검사한다.

선행 연결이 있는 오래된 미승인 추천은 새 상태 비교에 실패할 수 있으므로 다시 생성해야 한다.
이미 승인한 추천의 영수증 재조회와 기존 일정은 유지한다. 선행 관계가 없는 추천의 상태는
바꾸지 않는다. 코드/실행 버전 및 배포 여부는 프로젝트 배포 기록에서 별도로 확인한다.
