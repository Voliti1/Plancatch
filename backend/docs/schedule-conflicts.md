# 일정 시간 겹침 확인

`POST /api/schedules/conflicts`는 로그인한 사용자의 고정 할 일·반복 할 일과
승인 또는 전송된 배치 시간과 연결된 Google 기본 캘린더를 조회한다. 일정 등록·예약·Google 일정 쓰기는 하지 않는다.
마감일은 점 시각이므로 점유 시간 검사에서 제외한다. 유동 작업의 가능 기간,
추천·취소 배치는 제외한다. Google의 ‘한가함’ 일정과 본인이 참석을 거절한 일정도 제외한다.

요청에는 시간대가 있는 `start_at`, `end_at`, 선택적 `recurrence`를 넣는다.
할 일 수정은 `exclude_task_id`로 해당 원본과 배치를 제외한다. 배치 등록·수정은
`placement_task_id`로 원본 고정 시간을 제외하고, 수정 중인 배치는 `exclude_event_id`로
제외한다. 모든 참조 ID는 현재 계정 소유인지 먼저 검사한다.

양쪽 일정의 실제 점유 구간이 겹칠 때만 반환한다. 기존 일정이 끝나는 시각에 새 일정이
시작하면 겹치지 않는다. 반복 일정은 기존 회차 계산기를 재사용하며, 반복의 첫 시각과
현재 시각 중 늦은 쪽부터 최대 90일을 확인한다. 단일 일정도 최대 90일이다.
각 원본 종류 최대 1,000개, 각 반복 최대 201회, 응답 예시 최대 20개로 제한한다.
일부를 생략하면 `truncated`, 이후 기간이 남으면 `coverage_limited`로 표시한다.
응답의 `checked_from`, `checked_until`이 실제 검사 범위다.

Google 조회는 기존 읽기 경로의 자격 증명 갱신·계정 잠금·현재 연결별 전송 출처 매핑을
재사용한다. 갱신된 자격 증명은 뒤의 일정 조회가 실패해도 저장하지만 일정·작업은 바꾸지 않는다.
현재 계정의 같은 연결에 속하고 제목·시간이 일치하는 플랜캐치 전송 사본은 중복 검사에서
제외한다. 제목만 같거나 Google에서 내용이 달라진 일정은 별개로 검사한다. 종일 일정은
한국 날짜 0시부터 끝 날짜 0시 미만으로 해석한다. 반복 회차는 Google의 singleEvents 조회로 받는다.
읽기는 250건씩 최대 8페이지·원본 2,000건·페이지당 1MiB로 제한하며 페이지 사이 12초 예산을 확인한다.
다음 페이지가 남거나 중간 조회 실패·중복·파싱하지 못한 항목이 있으면
`google_state: partial`로 알리며 겹침 없음으로 확정하지 않는다. 네트워크/설정 오류는
`unavailable`, 재연결 필요는 `reconnect_required`, 조회 완료는 `checked`, 미연결은
`not_connected`다. 다른 캘린더·공유 캘린더는 이번 범위가 아니다.
형식 기준: [Google 일정 조회](https://developers.google.com/workspace/calendar/api/v3/reference/events/list),
[바쁨 및 참석 상태](https://developers.google.com/workspace/calendar/api/v3/reference/events).

화면은 등록 또는 시간·반복 변경을 저장하기 전에 확인한다. 겹침이 있으면 시간 변경과
명시적 저장 중 선택하며, 확인 실패 시 재시도 또는 확인 없는 저장을 선택한다.
Google만 확인하지 못한 경우 로컬 검사 결과를 유지하고 재시도·재연결 또는 명시적
‘구글 확인 없이 저장’을 제공한다. 입력을 바꾸면 이전 저장 허용을 폐기한다.
제목·메모·알림만 수정할 때는 재검사하지 않는다.
이 확인은 조회 당시의 안내이며 다른 요청과의 동시 등록을 잠그지 않는다.
기존 저장 API는 그대로 사용하므로 사용자가 의도적으로 겹치는 일정을 등록할 수 있다.
