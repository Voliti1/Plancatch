# 일정 시간 겹침 확인

`POST /api/schedules/conflicts`는 로그인한 사용자의 고정 할 일·반복 할 일과
승인 또는 전송된 배치 시간을 조회한다. 조회만 수행하며 등록·예약·Google 전송은 하지 않는다.
마감일은 점 시각이므로 점유 시간 검사에서 제외한다. 유동 작업의 가능 기간,
추천·취소 배치, Google에서만 관리하는 일정도 제외한다.

요청에는 시간대가 있는 `start_at`, `end_at`, 선택적 `recurrence`를 넣는다.
할 일 수정은 `exclude_task_id`로 해당 원본과 배치를 제외한다. 배치 등록·수정은
`placement_task_id`로 원본 고정 시간을 제외하고, 수정 중인 배치는 `exclude_event_id`로
제외한다. 모든 참조 ID는 현재 계정 소유인지 먼저 검사한다.

양쪽 일정의 실제 점유 구간이 겹칠 때만 반환한다. 기존 일정이 끝나는 시각에 새 일정이
시작하면 겹치지 않는다. 반복 일정은 기존 회차 계산기를 재사용하며, 반복의 첫 시각과
현재 시각 중 늦은 쪽부터 최대 90일을 확인한다. 단일 일정도 최대 90일이다.
각 원본 종류 최대 1,000개, 각 반복 최대 201회, 응답 예시 최대 20개로 제한한다.
일부를 생략하면 `truncated`, 이후 기간이 남으면 `coverage_limited`로 표시한다.
응답의 `checked_from`, `checked_until`이 실제 검사 범위다.

화면은 등록 또는 시간·반복 변경을 저장하기 전에 확인한다. 겹침이 있으면 시간 변경과
명시적 저장 중 선택하며, 확인 실패 시 재시도 또는 확인 없는 저장을 선택한다.
입력을 바꾸면 이전 저장 허용을 폐기한다. 제목·메모·알림만 수정할 때는 재검사하지 않는다.
이 확인은 조회 당시의 안내이며 다른 요청과의 동시 등록을 잠그지 않는다.
기존 저장 API는 그대로 사용하므로 사용자가 의도적으로 겹치는 일정을 등록할 수 있다.
