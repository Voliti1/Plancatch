# 실제 빈 시간과 작업 순서를 반영한 마감 위험도

기존 `GET /api/deadlines/{id}/readiness`에 `capacity_risk`를 추가한다. 종전 준비 상태 필드와
계산 의미는 유지하며 새 화면은 이 새 결과를 우선 표시한다. DB 구조 변경·계산 결과 저장·AI 호출·
작업/배치 자동 생성·이동은 없다. 과거 배치를 작업 완료로 간주하지 않는다.

## 계산 범위

- 안전 마감(없으면 공식 마감)과 현재 시각 사이, 최대 앞으로 31일을 확인한다.
  31일보다 먼 마감은 범위를 명시하고 전체 여유 판단을 보류한다.
- 이 마감일의 작업 최대 200개와 필요한 미완료 선행 작업을 같은 계정 안에서 찾아 함께 계산한다.
  완료한 선행 작업의 상위 작업을 다시 요구하지 않는다. 선행 연결 최대 1,000개·전체 확인 작업 200개.
  다른 마감일의 미배치 작업은 선행 관계가 없는 한 작업량에 포함하지 않는다.
- 계정별 요일 시간과 날짜별 휴무/대체 시간을 사용한다. 고정/반복 일정 및 approved/synced 배치를
  제외한 시간만 빈 시간이다. 다른 마감일의 확정 일정·종일·반복 예외도 포함한다. 종류별 1,000개와
  반복 확장 총 2,000개 상한. 일부만 확인되면 여유가 있다고 결론 내리지 않는다.
- fixed 원래 시간은 배치가 하나라도 있으면(취소/추천 포함) 되살리지 않는다. 비활성 배치는 시간
  예약으로 계산하지 않는다. 같은 작업의 중복 구간은 합치며 다른 작업과 겹치는 구간은 유효한
  배치로 세지 않는다. 유동 작업은 저장한 작업 시간에도 들어맞아야 한다. 고정 일정은 지정한 실제
  시간으로 확인하므로 작업 가능 시간 밖에 있는 정상 고정 약속도 그대로 인정한다.
- 각 작업의 시작 가능 시각·완료 기한·연결된 공식/안전 기한을 지킨다. 선행 작업 완료/예상 종료
  이후에 후행을 배치하는 읽기 전용 모의 계산으로, 실제 예약이나 최적해 탐색은 아니다.
  기존 배치가 과거/개별 기한 밖/순서 이전에 있으면 조정 필요로 알린다. 조회만으로 옮기지 않는다.

## 결과 해석

- `completed`: 연결된 할 일이 모두 완료 표시됨.
- `overdue`: 공식 마감 지남. 안전 마감만 지났으면 attention.
- `insufficient`: 현재 가능 시간·기존 일정을 유지한다는 조건에서 자원량이나 개별 기간·선행
  순서의 낙관적 하한으로도 시간이 모자람을 확인. 모르는 소요시간이 있어도 확인한 작업량만으로
  부족함이 증명되면 부족으로 표시할 수 있다.
- `feasible`: 확인한 전체 범위에서 선후 관계와 겹침을 지키는 배치 방법을 찾음. 아직 저장/승인된
  일정이라는 의미는 아니고, 미래에 생기는 다른 일이나 소요시간 추정 오류를 보장하지 않는다.
- `tight`: 배치 방법은 찾았지만 남는 시간 ≤ max(30분, 전체 작업량의 20%)이거나 24시간 이내.
- `attention`: 기존 배치 조정이나 원문 마감일 확인이 필요하거나 모의 계산에서 전체 배치 방법을
  찾지 못했지만 수학적 시간 부족으로 단정할 수 없는 경우. 탐색 실패만으로 shortage라 하지 않는다.
- `unknown`: 소요시간/반복 작업량이 불명확하거나 조회 범위·상한·구글 조회가 불완전함.
  불완전한 조회의 free_minutes/reserved_minutes는 null로 반환해 실제 빈 시간처럼 표시하지 않는다.

working_minutes는 저장한 가능 시간, free_minutes는 현재 등록 일정 후 추가로 쓸 수 있는 시간이다.
reserved_minutes는 기한·가능 시간·겹침·순서가 유효한 기존 배치다. required_minutes는 미완료 작업과
필요한 선행 작업 전체 소요시간이며 불명확하면 null, known_required_minutes는 확인한 하한이다.
to_schedule_minutes는 유효 배치로 확보하지 못한 작업량, unplaced_minutes는 모의 계산에서도
확보하지 못한 양이다. 숫자를 확정하지 못한 경우 0이 아니라 null이다. 이는 성공 확률이 아니다.

## Google 선택과 일관성

기본은 로컬 일정만 읽는다. `include_google=true` 또는 ‘구글 바쁨 일정도 포함해 확인’을 선택할
때만 기존 Google 읽기 권한·페이지 제한으로 바쁨 일정을 읽는다. 개인정보/일정 원문을 AI로 보내지
않으며 Google 이벤트 쓰기를 하지 않는다. 기존 읽기 전송은 필요하면 인증 토큰을 갱신할 수 있다.
미연결·권한/네트워크 오류·일부 조회·연결 바뀜·조회 중 마감 변경은 unknown으로 안내한다.
완료한 작업만 있거나 이미 마감 지났으면 불필요한 Google 요청을 하지 않는다.

조회는 사용자 잠금 안에서 일관되게 계산하되 Google 대기 동안 잠금/DB 연결을 반환한다.
돌아온 뒤 잠금을 다시 잡고 날짜·작업·연결을 새로 읽는다. 상위 작업은 한꺼번에 조회하고 큰 작업
설명/배치 오류 본문은 읽지 않는다. 30개 작업의 기본 계산은 고정된 11개 읽기(작업 수에 비례하지
않음), 깊은 선행 연결도 반복 조회 없이 처리하는 검사를 둔다. 실제 시각은 assessed_at으로 알린다.

기존 자동 배치와 공유하는 시간대·휴무/Google 읽기/구간 연산을 재사용하되 준비 상태 조회가
미리보기를 DB에 쓰거나 작업을 승인하지는 않는다. 준비 상태 계산은 다른 마감일의 미배치 작업까지
전부 풀어 주는 전역 최적화가 아니다. 실제 변경 후에는 다시 확인해야 한다.

## 검증과 복구

휴무·다른 일정·계정 분리·반복 제외일·중복/겹침·개별 기간·모르는 작업량·긴 기한·다른 마감의
선행 작업·완료 선행의 상위 제외·기존 역순 배치·판단 상한·구글 선택/부분 조회·조회 중 기한 변경·
고정 쿼리 수를 합성 DB와 화면으로 검증한다. 실제 Google 개인 일정 테스트는 별도 승인이 있어야
진행하며 일반 배포 검사에는 Google 미연결 임시 계정만 사용한다.

모델/migration/의존성 변경 없음. 직전 PR #139 코드와 화면으로 함께 복구할 수 있고 같은 DB
revision과 사용자 자료·작업 순서를 유지한다. PR #139보다 더 오래된 코드로 복구할 때의 작업 순서
보호 조건은 여전히 해당 PR의 배포/복구 기록을 따른다. main 병합과 운영 배포 여부는 별도 기록한다.
