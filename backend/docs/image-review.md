# 이미지 일정 검토

- POST /api/sources/images: 로그인 후 multipart file 한 장과 선택 title(255자)을 저장한다.
  PNG/JPG/WebP/BMP/GIF/TIFF/AVIF를 실제 바이트로 디코딩한다. 브라우저 MIME은 신뢰하지 않는다.
  업로드5MiB·정규화후5MiB·1,200만 화소·단일 프레임 제한. 애니메이션·다중 페이지·HEIC·SVG·PDF는 거부한다.
  파일명/외부 URL은 저장 경로로 사용하지 않으며 PNG로 재인코딩하고 메타데이터를 제거한다.
  EXIF 회전을 적용하며 투명 배경은 흰색으로 합성해 검은 글자가 사라지는 것을 방지한다.
- EC2 nginx HTTP 공통 client_max_body_size6m을 설정한다. 이미지 본문은5MiB 이하이며
  나머지는 multipart 여유다. 백엔드8000은 공개하지 않는다. 디코딩은 프로세스당1개로 제한한다.
- backend/private_uploads에는 무작위키+SHA256 이름으로만 저장(폴더700/파일600), Git에서 제외한다.
  정적 공개 경로가 아니다. GET /api/sources/{id}/image는 소유권·해시 검사 후 PNG/no-store 반환.
  사용자가 자료를 삭제하면 파일도 제거한다. 마감일 연결 시 기존 삭제 보호 정책을 적용한다.
  원본 파일은 코드/PR 백업에 포함되지 않는다. 코드 복구 시 이 폴더/DB 데이터는 유지한다.
- 저장만으로 Gemini에 전송하지 않는다. 별도 화면에서 이미지 전송 동의를 받는다.
  POST /api/sources/{id}/ai-analyses에 allow_external_ai=true 및 image_sha256을 input_hash로 보낸다.
  동일 이미지 결과는 reuse_existing으로 재사용한다. 실패 후 재분석은 다시 동의하고 명시적으로 요청한다.
- Gemini1회로 본 공고 전사문+후보를 받는다. 추천공고/광고/졸업자격/날짜 없는 면접 제외를 지시한다.
  근거는 전사문에 실제 포함되어야 하며, 명시 시각과 다른 값 또는 날짜만 있는 값은 due_at=null로 보존한다.
  이는 OCR의 시각적 정확도를 수학적으로 검증한다는 뜻이 아니다. 이미지·짧은 근거와 함께 수동 검토한다.
- 연도가 같은 접수기간의 공유 연도는 읽을 수 있지만 연도가 넘어가는 범위의 연도를 추측하지 않는다.
  시각/제목이 없는 캡처는 시간을23:59로 채우거나 회사명을 이메일에서 유추하지 않는다.
  마감 후보는 기본 미선택, 원본 이미지 확인→제목/일시 수정·선택→저장→명시적 승인 순서다.
  자동 등록 API는 이미지 자료를 거부한다. 승인 후 기존 Deadline/캘린더 표시와 연결한다.
- 이미지 교체 API는 없으며 이미지 자료 PATCH는 제목만 허용한다. 재업로드는 새 자료다.
  기존URL HTML 경로는 외부AI 없이 유지, 텍스트 경로도 유지한다. PDF·다중 이미지·파일OCR는 후속 범위다.
  DB 모델/마이그레이션 변경 없음(기존 image/storage_key 필드 사용), Pillow13.0.0만 추가한다.
- 계정 삭제의 디스크 정리는 별도 운영 과제이며 사용자계정 삭제 API는 현재 없다.
  운영 검증 계정은 Source DELETE로 테스트 이미지부터 정리한 뒤 해당 계정만 정리한다.
