# Google 캘린더 명시적 등록

마감일/할 일 상세의 ‘Google 전송 미리보기’에서 제목·시간을 확인하고
‘확인 후 Google에 등록’을 눌러야 본인 Google 기본 캘린더에 전송합니다.
자료 저장/분석 승인/내부 배치 저장만으로 Google에 보내지 않습니다.

- 확인한 마감일: 공식 마감 시각부터 1분짜리 표시. 안전 마감일은 별도 전송하지 않습니다.
- 고정 할 일: 시작·종료가 있고 배치가 없는 경우 직접 전송합니다.
- 배치가 있는 할 일: 확정/사용자 승인 배치에서 보냅니다. 유동 가능 기간은 일정이 아닙니다.
- 제목·시작·종료만 전송합니다. 메모/원문/참석자/첨부를 보내지 않고 기본 알림도 끕니다.
- 이후 로컬/Google 수정·삭제는 자동 동기화하지 않습니다. 기존 Google 일정을 덮어쓰지 않습니다.

## API

인증 필수, 응답은 no-store. 기존 calendar.events.owned 권한/서버 암호화 키를 사용합니다.

`POST /api/integrations/google-calendar/exports/preview`

입력 `{kind: deadline|task|event, item_id: UUID}`. DB 쓰기/Google 요청 없이 소유권·시간·연결을 확인합니다.
출력 title/start_at/end_at/status/changed/note/preview_token. 상태는 new/pending/sent/conflict/blocked.
10분짜리 암호화 토큰은 사용자·항목·내용·현재 연결 시점에 묶입니다. 토큰은 로그/영구 브라우저 저장 금지.

`POST /api/integrations/google-calendar/exports/confirm`

위 입력에 `preview_token`과 boolean `confirm: true`를 추가합니다. 제목/시간 임의 전달 불가.
최초 확인은 미리보기 이후 내용 변경을 거부합니다. 이전 전송 기록은 확인했던 내용 그대로 재사용합니다.
출력 `{status: sent, google_event_id, already_sent}`. 미연결/변경/만료/충돌409,
항목 없음404, 미확정 시간/동의 누락422, 불확실 응답502/제한503.

## 중복·실패 처리

외부 요청 전에 고정 Google ID와 불변 전송 내용을 DB에 커밋합니다. 사용자 행 잠금으로
동시 등록/재연결/해제를 직렬화합니다. 같은 사용자·kind·item_id는 한 기록만 저장합니다.
할 일 직접 전송과 그 배치 전송도 교차 중복을 막습니다. 여러 별도 배치는 각각 전송 가능합니다.
동일 제목의 별도 로컬 항목은 서로 다른 일정입니다.

재시도는 같은 ID로 GET 후 필요할 때만 POST합니다. POST 응답이 유실돼도 새 ID를 발급하지 않습니다.
409 뒤 조회 지연은 pending을 유지합니다. 삭제/수정/소유 표시 불일치는 conflict로 차단합니다.
sent는 원격 일정이 나중에 삭제돼도 자동 재생성하지 않습니다.
연결을 다시 승인하면 같은 Google 계정이어도 연결 시점이 바뀌므로 기존 항목 재전송을 차단합니다.
연결이 바뀐 경우 Google에서 이전 등록을 확인해야 하며, 신규 로컬 항목의 등록은 가능합니다.

전송한 항목은 Google 조회 결과와 제목·시간·내부 ID가 정확히 같을 때만 자체 캘린더에서 중복 숨김합니다.
Google나 로컬에서 바뀐 일정은 별도로 남겨 차이를 확인할 수 있습니다.

## DB와 복구

20261026_0008은 google_calendar_exports 테이블만 추가합니다. 기존 행은 변경하지 않습니다.
로컬 항목을 지워도 전송 기록/스냅샷은 중복 방지를 위해 보존하며 계정 삭제 시 함께 삭제됩니다.
일반 코드 롤백은 0008과 전송 기록을 유지합니다. 자동 downgrade/사용자 데이터 복원 금지.
구조만 백업한 뒤 추가 마이그레이션하고 이전 코드·실행 빌드를 보관합니다.

검증은 가상 Google 응답과 격리 DB를 사용합니다. 실제 개인 캘린더 일정 등록은 사용자가
연결 후 선택한 항목의 미리보기를 보고 직접 승인하여 확인해야 합니다.
