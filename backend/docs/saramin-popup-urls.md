# 사람인 팝업 공고 주소

2026-11-10 재현: `/zf_user/jobs/relay/pop-view?rec_idx=55504409`는 HTTP 200으로
공개 접수기간을 내려주지만 이전 전용 URL 검사에서 제외됐다. 그 결과 일반 본문 범위가
없는 팝업에서는 마감일 선택지와 회사명을 읽지 못했고, 같은 공고의 `/zf_user/jobs/view`
주소에서는 정상 추출됐다.

`/zf_user/jobs/view`, `/zf_user/jobs/relay/view`와 함께 정확한
`/zf_user/jobs/relay/pop-view` 경로를 사람인 접수기간·회사명·저장된 원문 결합 검사에
사용한다. 전용 URL 검사는 공식 호스트, 숫자 `rec_idx` 한 개, 허용 포트와 자격 증명
없음을 계속 확인한다. 회사명은 같은 공고 ID의 기업 정보 영역에서 읽는다.

릴레이/팝업의 canonical은 같은 원점·같은 `rec_idx`의 `/zf_user/jobs/view` 주소 한 개만
최대 한 번 따라간다. 최초 페이지의 로그인 차단, canonical 충돌, 다른 공고/호스트,
robots·공개 DNS·응답 크기·전체 시간 제한은 유지한다. 임의 iframe/JS 실행이나 로그인
우회는 추가하지 않는다. 사용자가 제출한 팝업 주소는 보존하고 가져온 일반 주소를 검토
스냅샷에 별도로 남긴다. URL 경로는 외부 AI를 호출하지 않는다.

기존 저장된 원문은 변경하지 않는다. 예전 추출에서 검토 정보가 비어 있었다면 해당 자료를
다시 추출하고 검토하거나 같은 URL로 새로 등록해야 한다. 이미 같은 공고의 정상 원문을
가진 팝업 자료는 새 URL 인식 검사로 다시 검토할 수 있다.
