# 캐치 HTML 접수기간 추출·검토

캐치 공개 채용공고의 `div#view2_{공고번호}.recr_pop_dday` 안에서 `p.t1`의 마감일을
읽습니다. 기존 자료 추출 → HTML 마감일 검토 → 수정·승인 흐름을 사용합니다.
승인 전에는 마감일을 생성하지 않으며 Gemini를 호출하지 않습니다.

## 같은 공고의 날짜 대조

- 공식 `catch.co.kr` / `www.catch.co.kr`의 `/NCS/RecruitInfoDetails/{숫자}`만 지원합니다.
  DOM의 공고 번호가 요청 URL과 같아야 하며 숨겨진 요소는 제외합니다.
- 캐치의 JSON-LD `JobPosting`에는 `url`이나 `@id`가 없을 수 있습니다. 이 예외는
  캐치 어댑터에만 적용합니다. 같은 공고의 canonical URL, 유일한 `h1.subj` 제목,
  이에 대응하는 JobPosting 제목을 함께 확인해야 `validThrough`를 사용할 수 있습니다.
  제목의 `[회사명]` 접두사와 공백만 정규화합니다. 명시된 메타데이터 URL·공고 번호가
  다른 경우에는 그 데이터를 사용하지 않습니다.
- 화면의 월·일·요일·시각을 전체 일시와 대조합니다. 화면에도 연도가 있으면 함께
  대조합니다. 시간대 없는 완전한 메타데이터 일시는 기존 서비스 정책대로 한국 시간으로
  해석하고, 명시된 시간대가 있으면 이를 보존합니다.
- `2일 남았어요`를 수집 시각에 더하거나 현재 연도·제목의 연도를 넣지 않습니다.
  연도를 확인할 메타데이터나 화면의 마감 시각이 없으면 후보 일시를 비워 두며,
  날짜·요일·시각 충돌이나 여러 접수기간은 경고와 함께 직접 확인하도록 남깁니다.
- 다른 공고의 날짜, 추천 공고 및 임의 JavaScript는 읽지 않습니다. iframe 본문이나
  Nuxt 스크립트를 실행·추가 요청하지 않습니다. 기존 robots·공개 URL·응답 크기 정책과
  JSON-LD 16블록·총 100,000자·128노드·8단계 제한을 사용합니다. 화면 필드는 접수기간
  200자·제목 1,000자·각 8개로 제한하며, 초과 시 자동 날짜를 확정하지 않습니다.

2026-10-27 실제 공고 `574650`의 같은 응답에서 `~ 10.29(목) 14시`와
`validThrough: 2026-10-29T14:00:00+09:00`을 확인했습니다. 후보는 한국 시간
2026-10-29 14:00입니다. 기업이 변경할 수 있으므로 등록 전 원문 확인이 필요합니다.

## 응답·화면·반영

기존 `source_period.site`에 `"catch"`를 추가합니다. 화면에는 캐치 접수기간,
원문 마감일, 확정된 원문 일시를 기준으로 매초 갱신하는 현재 남은 기간을 표시합니다.
과거 사람인 응답의 `site` 생략도 계속 지원합니다. 검토 수정·승인과 revision·원문 변경
검사 및 중복 승인 방지는 기존 API를 사용합니다. 새 경로·환경변수·DB 변경은 없습니다.

백엔드와 프론트엔드 모두 코드 반영이 필요합니다. 이미 저장한 원문·분석은 자동으로
변경하지 않습니다. 기존 자료에 적용하려면 재추출 후 새 HTML 검토를 시작합니다.
마감일 승인만으로 Task·일정 블록이나 Google Calendar 이벤트를 생성하지 않습니다.

## 검증

`tests/test_catch_period.py`는 실제 사이트나 RDS를 사용하는 대신 합성 HTML과 격리된
SQLite로 원문/메타데이터 대조, 연도·시간 누락, 타 공고·숨김 요소 배제, 충돌·길이 제한,
검토 수정·승인·재조회·중복 승인을 확인합니다. SQLite는 오프셋을 보존하지 않으므로
DB 삽입 직전 일시도 확인합니다. 실제 URL은 기존 공개 추출 절차로 읽기만 검증합니다.

`frontend/tests/catch-period.spec.ts`는 PC·모바일에서 캐치 표시·근거·남은 시간,
제목 수정 후 일시 보존, 승인 후 새로고침, 연도 미확정·충돌 안내와 승인 제한을 확인합니다.
브라우저의 가상 응답은 테스트에만 있으며 운영 코드에서 가짜 결과를 제공하지 않습니다.

## 2026-10-27 보완

- `view2_{공고 ID}.recr_pop_dday p.t1`의 `span` 텍스트를 읽는다.
  `~ 11.08(일) 24시`는 표시 날짜의 끝을 뜻하며 동일 공고 메타데이터의 `23:59:59` 또는
  다음 날 `00:00:00`과 대조한다. 원래 메타데이터의 정확한 시점을 후보·저장에 유지한다.
  `24:30`, 실제로 다른 마감 시각, 날짜/요일 충돌은 계속 사용자 확인을 요구한다.
- 기업명은 해당 공고의 `printArea_{ID}` 또는 `view3_{ID}` 내부
  `a.name.gtm-recruitDetail-compInfo-click[href^="/Comp/CompSummary/"]`를 우선 읽는다.
  같은 이름의 반복 표시는 허용하지만 다른 공고·숨김·외부 링크는 사용하지 않는다.
- 사람인은 공고 ID가 일치하는 `jv_company.company_info_wrap_{ID} a.company_name`,
  자소설닷컴은 검증된 `initialEmploymentCompany.name`, 잡코리아·링커리어·잡플래닛은
  동일 공고로 검증한 `hiringOrganization.name`을 사용한다. 캐치도 슬롯 누락 시 동일 공고
  메타데이터만 보조로 사용한다. 접근 차단·정확한 영역 부재 시 기업명을 임의 생성하지 않는다.
- 검증한 기업명을 URL 검토 스냅샷에 저장하고 원본 자료·마감일 검토 화면에서 우선 표시한다.
  DB 구조 변경은 없다. 이전 분석 기록은 저장 당시 원문/결과를 유지하므로
  과거 실패 결과에 적용하려면 원문을 다시 추출한 뒤 새로 검토한다.
